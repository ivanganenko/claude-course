# Модуль 02. Установка и первые шаги в Claude Code

> **Зачем:** Claude Code — это Claude, который умеет сам читать и менять файлы и выполнять команды на твоём компьютере. В этом модуле ты установишь его, освоишь минимум терминала и научишься управлять сессией так, чтобы агент делал то, что нужно, и не делал лишнего. **Время:** ~3 ч. **Нужно:** модуль 01; компьютер с Windows, macOS или Linux; аккаунт Claude с доступом к Claude Code (подписка Pro/Max/Team/Enterprise или API key).

## Что ты будешь уметь

- ориентироваться в терминале: где ты находишься, как перейти в папку, посмотреть файлы, создать папку;
- установить Claude Code, проверить установку и начать сессию в нужной папке;
- давать Claude задачи на создание и изменение файлов и осознанно подтверждать или отклонять его действия;
- переключать permission modes и понимать, когда какой уместен;
- откатывать неудачные изменения, очищать и продолжать сессии;
- следить за расходом context и выбирать модель.

## 1. Минимум терминала

**Терминал** (командная строка) — окно, где ты управляешь компьютером текстовыми командами. Claude Code живёт в терминале, поэтому без пяти базовых команд не обойтись.

**Какой терминал открыть:**

| ОС | Что открыть | Оболочка (shell) |
|----|-------------|------------------|
| Windows | «Пуск» → набери `PowerShell` → Windows PowerShell (или «Терминал Windows») | PowerShell |
| macOS | Программы → Утилиты → Терминал | zsh (похож на bash) |
| Linux | Терминал | bash |

**Shell** (оболочка) — программа, которая понимает твои команды. PowerShell (Windows) и bash/zsh (macOS, Linux) — разные оболочки, но базовые команды похожи.

**Путь** — адрес файла или папки:
- Windows: `C:\Users\anna\claude-practice\notes.md` (разделитель `\`);
- macOS/Linux: `/Users/anna/claude-practice/notes.md` или `/home/anna/...` (разделитель `/`).

**Домашняя папка** — твоя личная папка пользователя. Её короткое имя — `~` (тильда). Работает и в PowerShell, и в bash: `~/claude-practice` = «папка claude-practice в моей домашней папке». В PowerShell домашнюю папку также можно записать как `$HOME`.

**Пять команд:**

| Что сделать | PowerShell (Windows) | bash / zsh (macOS, Linux) |
|-------------|---------------------|---------------------------|
| Где я сейчас? | `pwd` | `pwd` |
| Что в этой папке? | `ls` или `dir` | `ls` (подробно: `ls -la`) |
| Перейти в папку | `cd ~\claude-practice` | `cd ~/claude-practice` |
| На уровень выше | `cd ..` | `cd ..` |
| Создать папку | `mkdir имя` | `mkdir имя` |
| Показать содержимое файла | `cat файл.txt` (или `Get-Content файл.txt`) | `cat файл.txt` |
| Скопировать файлы | `Copy-Item откуда\* куда\` | `cp откуда/* куда/` |

Полезные приёмы:
- **Tab** — дополняет имя файла или папки. Набери `cd ~/cl` и нажми Tab.
- **Стрелка вверх** — предыдущая команда.
- Если путь содержит пробелы, бери его в кавычки: `cd "C:\Users\anna\Мои документы"`.

> **Почему так?** Терминал кажется архаичным, но для агента это идеальный интерфейс: всё — текст, каждое действие — команда, которую видно и можно повторить. Тебе не нужно становиться экспертом: достаточно понимать, *в какой папке* ты находишься, потому что Claude Code работает именно с ней.

## 2. Установка Claude Code

Выбери **один** способ для своей ОС. Перед установкой прочитай команду: она скачивает и запускает официальный установщик.

**Windows (PowerShell):**

```powershell
irm https://claude.ai/install.ps1 | iex
```

Альтернатива — через менеджер пакетов winget:

```powershell
winget install Anthropic.ClaudeCode
```

На Windows также установи **Git for Windows** (https://git-scm.com/downloads/win): Claude Code использует входящий в него Git Bash для выполнения команд, а сам git понадобится в модуле 05.

**macOS / Linux / WSL:**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Проверка.** Закрой и снова открой терминал (чтобы он «увидел» новую программу), затем:

```bash
claude --version
```

Должна появиться версия. Если что-то не так — команда диагностики:

```bash
claude doctor
```

Она проверяет установку и подсказывает, что исправить.

Частые проблемы:
- `claude: command not found` / «имя "claude" не распознано» — перезапусти терминал; если не помогло — запусти `claude doctor` или посмотри раздел установки в документации.
- Команды установки со временем могут меняться. Актуальная инструкция всегда на https://code.claude.com/docs.

> **Почему так?** Официальный установщик сам кладёт программу в нужное место и умеет её обновлять. Команда «скачать и запустить скрипт» (`irm … | iex`, `curl … | bash`) удобна, но запускай так только скрипты из источника, которому доверяешь, — и всегда смотри на адрес.

## 3. Папка для практики и первая сессия

Claude Code работает **в той папке, из которой ты его запустил**. Эта папка — его «рабочий стол»: файлы в ней он читает и меняет, команды запускает в ней.

Для курса создадим отдельную папку `~/claude-practice` и по подпапке на модуль:

```powershell
# Windows PowerShell
mkdir ~\claude-practice\02-basics
cd ~\claude-practice\02-basics
claude
```

```bash
# macOS / Linux
mkdir -p ~/claude-practice/02-basics
cd ~/claude-practice/02-basics
claude
```

(`mkdir -p` в bash создаёт и промежуточные папки; PowerShell делает это и без флага.)

**Первый запуск.** Claude Code предложит войти в аккаунт — следуй инструкциям в терминале (обычно открывается браузер). Он также может спросить, доверяешь ли ты этой папке, — для своей practice-папки отвечай «да».

После входа ты увидишь поле ввода. Пиши задачу обычным языком, как в чате:

```text
Какие файлы есть в этой папке? Что ты можешь здесь делать?
```

> **Почему так?** Отдельная папка — это граница безопасности и чистоты эксперимента. Claude Code подхватывает `CLAUDE.md` и настройки из текущей и родительских папок. Если запустить его в папке курса, практическая сессия «увидит» инструкции учителя. А если запустить в домашней папке целиком — агенту будут доступны все твои документы. Маленькая отдельная папка = понятно, что агент видит и что может изменить.

## 4. Как Claude Code работает

Обычный чат умеет только отвечать текстом. Claude Code — **agent** (агент): модель, которая может вызывать **tools** (инструменты) и действовать по шагам.

```text
Ты: «Сделай из заметок встречи список задач в tasks.md»
   ↓
Claude думает: сначала нужно прочитать заметки
   → tool Read: читает meeting-notes.txt         ← видит содержимое
Claude думает: теперь создам файл
   → tool Write: создаёт tasks.md                ← спрашивает твоё разрешение
   ↓
Claude: «Готово, вот что я сделал…»
```

Основные tools, которые ты будешь видеть в сессии:

| Tool | Что делает | Спрашивает разрешение? (в режиме default) |
|------|-----------|-------------------------------------------|
| Read | читает файл | обычно нет |
| Glob, Grep | ищет файлы по имени и текст в файлах | обычно нет |
| Edit, Write | меняет или создаёт файл | да, показывает изменения |
| Bash | выполняет команду в терминале | да (кроме разрешённых) |

Важные следствия:

- **Claude видит только то, что прочитал.** Он не знает содержимое файлов, пока не откроет их. Если ответ «мимо» — проверь, читал ли он нужный файл.
- **Перед правкой Claude показывает diff** (разницу «было → стало»). Это твой момент контроля: читай его.
- **Каждый прочитанный файл и вывод команды попадает в context.** Прочитал большой файл — context заметно вырос (это ты измеришь в упражнении 6).
- **Агент может ошибаться в действиях**, а не только в словах: удалить не тот файл, выполнить не ту команду. Поэтому есть разрешения.

> **Почему так?** Цикл «подумал → вызвал tool → посмотрел на результат → решил, что дальше» позволяет решать задачи, которые нельзя сделать одним ответом: найти нужный файл, исправить, проверить, исправить снова. Подробно agent loop разберём в модуле 09.

## 5. Разрешения и permission modes

Когда Claude хочет изменить файл или выполнить команду, он показывает, **что именно** собирается сделать, и спрашивает. Обычно варианты такие (точные формулировки зависят от версии):

- **да** — выполнить один раз;
- **да, и больше не спрашивать** о похожих действиях в этой сессии;
- **нет** — и написать Claude, что сделать иначе.

Отказ — нормальная часть работы. Claude не «обижается»: он получает сообщение, что действие отклонено, и ждёт твоих указаний или предлагает другой путь.

**Permission modes** (режимы разрешений) определяют, о чём Claude спрашивает. Переключаются клавишами **Shift+Tab** — текущий режим отображается под полем ввода.

| Режим | Что происходит | Когда использовать |
|-------|---------------|--------------------|
| `default` | спрашивает перед правкой файлов и командами | по умолчанию; новая задача, незнакомая папка |
| `acceptEdits` | правит файлы без вопросов, команды — всё ещё спрашивает | ты понимаешь задачу, правок много, хочешь не отвлекаться |
| `plan` | только читает и составляет план, ничего не меняет | сложная задача: сначала обсудить план (подробно — модуль 04) |
| `bypassPermissions` | делает всё без вопросов | **опасно**; только в изолированной среде (виртуальная машина, контейнер). Включается флагом `--dangerously-skip-permissions` — в этом курсе не используем |

Shift+Tab по кругу переключает режимы: `default` → `acceptEdits` → `plan` → … Точный порядок и набор могут отличаться между версиями — смотри индикатор режима и `/help`.

> **Почему так?** Это компромисс между скоростью и контролем. Спрашивать о каждом действии — безопасно, но утомительно: на десятой правке ты перестанешь читать и начнёшь нажимать «да» не глядя, а это хуже, чем осознанный `acceptEdits`. Хорошая практика: `default` для нового, `acceptEdits` — когда план понятен и есть возможность откатить (rewind, git), `plan` — когда сначала нужно подумать.

## 6. `@` — указать файл, `!` — выполнить команду самому

**`@путь` — упомянуть файл.** Начни набирать `@` и имя — появится автодополнение. Содержимое файла попадёт в context вместе с сообщением.

```text
Сделай из @meeting-notes.txt таблицу задач: кто, что, срок.
```

Это надёжнее, чем «посмотри заметки»: Claude точно знает, какой файл нужен, и не тратит шаги на поиск.

**`!команда` — bash mode.** Если начать сообщение с `!`, команда выполнится сразу, без участия Claude, а её вывод попадёт в разговор — Claude его увидит.

```text
!ls
!cat tasks.md
```

На Windows команды в этом режиме обычно выполняет Git Bash, поэтому `ls` и `cat` работают и там.

Когда что использовать:
- нужно, чтобы Claude **поработал** с файлом — `@файл` и задача;
- нужно самому **быстро проверить** результат (какие файлы появились, что в файле) — `!команда`;
- нужно, чтобы Claude **запустил** что-то и разобрался с результатом — попроси словами («запусти скрипт и исправь ошибки»).

> **Почему так?** `!` экономит время и tokens: простую проверку не нужно «объяснять» модели — ты просто выполняешь команду, а Claude видит результат и может на него опереться. `@` убирает двусмысленность: модель не гадает, какой файл ты имел в виду.

## 7. Управление сессией: прервать, откатить, очистить, продолжить

| Действие | Как | Когда |
|----------|-----|-------|
| Прервать Claude | **Esc** | видишь, что он пошёл не туда — не жди окончания |
| Откатиться назад | **Esc Esc** (дважды) или `/rewind` | правка оказалась неудачной; хочешь вернуться к прошлому сообщению/checkpoint |
| Очистить разговор | `/clear` | начинаешь новую, не связанную задачу |
| Продолжить последнюю сессию | `claude -c` (или `claude --continue`) при запуске | закрыл терминал и хочешь вернуться к той же работе |
| Выбрать старую сессию | `/resume` | нужна не последняя, а одна из предыдущих |
| Справка | `/help` | забыл команду или хочешь узнать, что есть в твоей версии |

**Rewind** (откат) работает с checkpoints — снимками состояния, которые Claude Code сохраняет по ходу работы. В меню отката выбираешь точку в разговоре, и можно вернуть разговор, файлы или и то и другое (набор вариантов зависит от версии).

Ограничение: откат отслеживает правки, сделанные инструментами редактирования Claude. Изменения, сделанные командами в терминале (например, удаление файла через `rm`) или тобой вручную в другом редакторе, он может не вернуть. Для надёжной истории изменений есть git — модуль 05.

**Esc vs `/clear`:** Esc останавливает текущее действие, но разговор остаётся. `/clear` стирает историю разговора (файлы при этом не меняются) — Claude начинает «с чистого листа» в той же папке.

> **Почему так?** Работа с агентом — это серия попыток. Дешёвый откат делает эксперименты безопасными: можно попросить смелое изменение и вернуться, если не понравилось. А `/clear` нужен потому, что старый разговор занимает context и может сбивать Claude с новой задачи (подробно — модуль 04).

## 8. Context, стоимость и модель

Помнишь context window из модуля 01? В Claude Code его можно увидеть.

- **`/context`** — показывает, сколько context занято и чем: системные инструкции, инструменты, файлы памяти, сообщения. Используй, когда сессия «тяжелеет» или перед большой задачей.
- **`/cost`** — показывает расход tokens/стоимость текущей сессии. В зависимости от версии и типа аккаунта (подписка или API) статистика может выглядеть по-разному, а в новых версиях может быть команда `/usage` — проверь `/help`.
- **`/model`** — выбор модели. Алиасы: `opus`, `sonnet`, `haiku` (см. модуль 01, раздел 7). Например, переключиться на быструю модель для простой задачи, а для сложной — на сильную.

Как читать `/context`: ещё до твоего первого сообщения там уже что-то есть — системные инструкции и описания tools. Это нормальная «базовая нагрузка». Дальше каждый прочитанный файл и каждый ответ добавляют своё.

> **Почему так?** Context — ограниченный ресурс, и он же влияет на качество: чем больше в нём лишнего, тем хуже Claude фокусируется на задаче. Привычка смотреть `/context` — как привычка смотреть на уровень топлива: не каждую минуту, но перед длинной дорогой обязательно.

## Глоссарий

| Термин | Что значит |
|--------|-----------|
| терминал | окно для текстовых команд |
| shell | программа, исполняющая команды: PowerShell, bash, zsh |
| путь (path) | адрес файла или папки в файловой системе |
| домашняя папка (`~`) | личная папка пользователя |
| рабочая папка (working directory) | папка, из которой запущен Claude Code; с ней он работает |
| agent | модель, которая вызывает tools и действует по шагам |
| tool | действие, доступное агенту: Read, Edit, Write, Bash, Glob, Grep |
| diff | показ изменений «было → стало» |
| permission mode | режим разрешений: `default`, `acceptEdits`, `plan`, `bypassPermissions` |
| checkpoint | сохранённая точка, к которой можно откатиться |
| rewind | откат разговора и/или файлов к checkpoint |
| bash mode | ввод `!команда` — команда выполняется напрямую |
| session | одна сессия работы с Claude Code: история разговора в конкретной папке |

## Вопросы для самопроверки

1. Почему важно, из какой папки ты запускаешь `claude`? Что будет, если запустить его в домашней папке?
2. Чем `cd ..` отличается от `cd ~`?
3. Claude прочитал файл и предлагает его изменить. Что ты должен посмотреть, прежде чем согласиться?
4. Чем `acceptEdits` отличается от `default` и от `bypassPermissions`? Когда ты включишь `acceptEdits`?
5. Ты отклонил действие Claude. Что произойдёт дальше и как направить его в нужную сторону?
6. В чём разница между Esc, Esc Esc и `/clear`?
7. Ты удалил файл через `!rm` и хочешь его вернуть через rewind. Получится ли? Почему?
8. Зачем смотреть `/context` и что ты ожидаешь там увидеть после чтения большого файла?
