## Упражнение 1. Трасса agent loop  ·  ⏱ ~20 мин  ·  обязательное

**Цель:** увидеть agent loop в работе Claude Code и записать его шаги.
**Зачем:** когда понимаешь, из каких шагов состоит работа агента, ты понимаешь, куда уходят tokens, где агент может ошибиться и где его остановить.

**Шаги:**
1. Открой сессию в `~/claude-practice/todo-app`, выполни `/clear`. Режим — `default` (чтобы Claude спрашивал разрешения; это заставит его «остановиться» на каждом действии).
2. Дай задачу, которую нельзя решить без нескольких шагов:
   ```
   Сколько в todos.json невыполненных задач с приоритетом high, и совпадает ли это
   с тем, что показывает `python todo.py list`? Если не совпадает — объясни почему.
   ```
   (на macOS/Linux может понадобиться `python3`)
3. Наблюдай: какие tools вызывает Claude (Read, Grep, Bash…), в каком порядке, что видит в ответ. Разрешай действия по одному.
4. Создай файл `agent-loop-trace.md` (можно в блокноте) с таблицей:
   `№ | что модель, судя по всему, хотела узнать | tool и аргумент | что получила | как это повлияло на следующий шаг`.
5. Ответь в конце файла на 2 вопроса:
   - На каком шаге модель *изменила план* из-за результата tool?
   - Что было бы, если бы ты на шаге с `Bash` нажал «нет»? (можешь проверить на практике: повтори задачу после `/clear` и откажи.)

**Что сдать на проверку:** файл `agent-loop-trace.md`.
**Критерии готовности:**
- [ ] В таблице ≥ 4 шагов с реальными названиями tools.
- [ ] Для каждого шага указано, как результат повлиял на следующее действие.
- [ ] Есть ответ, где модель скорректировала план.
- [ ] Есть наблюдение или обоснованное предположение про отказ в разрешении.

## Упражнение 2. Explore: изоляция контекста на практике  ·  ⏱ ~25 мин  ·  обязательное

**Цель:** сравнить расход context при изучении проекта напрямую и через subagent Explore.
**Зачем:** на больших проектах это разница между сессией, которая «тупеет» через полчаса, и сессией, которая остаётся чистой весь день.

**Шаги:**
1. **Вариант А (без subagent).** `/clear`, затем `/context` — запиши, сколько занято. Дай задачу:
   ```
   Прочитай все файлы проекта (код, тесты, README, todos.json) и объясни,
   как устроено хранение задач и откуда берётся путь к файлу.
   НЕ используй subagents — сделай сам.
   ```
   После ответа снова `/context`. Запиши число.
2. **Вариант Б (через Explore).** `/clear`, `/context`. Дай задачу:
   ```
   Используй subagent Explore, чтобы выяснить, как устроено хранение задач
   и откуда берётся путь к файлу. Верни сводку: до 7 пунктов со ссылками на файлы и функции.
   ```
   После ответа `/context`. Запиши число.
3. **Вариант В (параллельно).** `/clear`. Попроси запустить **три** Explore параллельно: CLI (`todo.py`), хранение (`storage.py`, `models.py`), тесты (`tests/`). Каждый — сводка до 5 пунктов, затем общая схема проекта.
4. Заполни таблицу в `explore-notes.md`:
   `вариант | context до | context после | прирост | качество ответа (1–5) | время (примерно)`.
5. Сделай вывод (3–5 предложений): когда Explore выгоден, а когда нет. Учти, что todo-app маленький — как изменилась бы разница на проекте из 300 файлов?

**Что сдать на проверку:** `explore-notes.md` с таблицей и выводом.
**Критерии готовности:**
- [ ] Есть реальные числа из `/context` для вариантов А и Б.
- [ ] В варианте Б/В видно, что работал subagent (студент описывает, что видел в интерфейсе).
- [ ] Вывод объясняет **почему** прирост context разный.
- [ ] Вывод упоминает цену: subagent не бесплатен.

## Упражнение 3. Свой read-only `code-reviewer`  ·  ⏱ ~30 мин  ·  обязательное

**Цель:** создать subagent, который делает ревью кода и физически не может его менять.
**Зачем:** ревью «свежими глазами» ловит ошибки, которые пропускает автор. А read-only гарантирует, что ревьюер не начнёт «чинить» по-своему без твоего ведома.

**Шаги:**
1. Создай `.claude/agents/code-reviewer.md` в `todo-app`. Сам напиши frontmatter и system prompt (не копируй пример из README целиком — адаптируй):
   - `tools` — только чтение;
   - `description` — **когда** звать агента;
   - в теле — что проверять, формат ответа (таблица с серьёзностью), что делать при сомнениях.
2. Проверь, что агент виден: `/agents` (если не видно — перезапусти `claude -c`).
3. Подготовь материал для ревью. Если ты в модуле 05 исправил все баги — внеси новую ошибку сам, например в `done` поменяй сравнение id так, чтобы отмечалась не та задача. Если баги ещё есть — отлично, они и будут материалом.
4. Вызови агента явно:
   ```
   Используй subagent code-reviewer, чтобы сделать ревью todo.py и storage.py.
   ```
5. Проверь read-only: попроси
   ```
   Используй subagent code-reviewer и попроси его сразу исправить найденные проблемы.
   ```
   Что произошло? Кто в итоге (если кто-то) поправил файл — subagent или основная сессия? Проверь `git status`.
6. Запиши в `reviewer-notes.md`: сколько реальных проблем нашёл агент, были ли ложные срабатывания, что показал шаг 5.

**Что сдать на проверку:** `.claude/agents/code-reviewer.md` и `reviewer-notes.md`.
**Критерии готовности:**
- [ ] `tools` не содержит `Edit`, `Write`, `Bash`.
- [ ] `description` описывает ситуации вызова («после правок», «перед коммитом», «проверь код»).
- [ ] В system prompt задан формат ответа и порядок проверки.
- [ ] Агент нашёл хотя бы одну реальную ошибку.
- [ ] Шаг 5 выполнен, вывод записан (subagent не смог править сам).

## Упражнение 4. `test-writer` для todo-app  ·  ⏱ ~35 мин  ·  обязательное

**Цель:** создать subagent, который пишет и запускает тесты, но не трогает код приложения.
**Зачем:** тесты — способ «дать Claude проверить себя» (модуль 05). Отдельный агент для тестов не подстраивает тесты под только что написанный код и не «чинит» код, чтобы тесты прошли.

**Шаги:**
1. `git status` — рабочее дерево чистое? Если нет — закоммить.
2. Создай `.claude/agents/test-writer.md`:
   - `tools`: чтение + `Write`, `Edit`, `Bash` (нужно создавать файлы тестов и запускать `pytest`);
   - `model` — выбери и **объясни выбор** комментарием в своих заметках;
   - в теле: писать тесты только в `tests/`; **не менять** `todo.py`, `models.py`, `storage.py`, `todos.json`; использовать временный файл данных (подсказка: `storage.py` берёт путь из env `TODO_FILE`, а у pytest есть `tmp_path` и `monkeypatch`); запускать `python -m pytest -q`; если тест падает из-за ошибки в коде приложения — **не чинить**, а сообщить; формат итогового ответа.
3. Вызови:
   ```
   Используй subagent test-writer, чтобы покрыть тестами storage.py
   и команду stats.
   ```
4. Проверь результат сам:
   - `git status` и `git diff` — какие файлы изменены? Только `tests/`?
   - `python -m pytest -q` — сколько тестов, сколько прошло?
   - `todos.json` не изменился?
5. Если агент нарушил границы (изменил код приложения или `todos.json`) — уточни system prompt и повтори (`git restore .` перед повтором).

**Что сдать на проверку:** `.claude/agents/test-writer.md`, новые файлы в `tests/`, вывод `pytest` (скопируй в `test-writer-notes.md`), заметка про выбор модели.
**Критерии готовности:**
- [ ] Изменения только в `tests/` (подтверждено `git status`).
- [ ] Тесты не трогают реальный `todos.json` (используют `tmp_path`/`TODO_FILE`).
- [ ] `pytest` запускается; падения, если есть, объяснены как баги приложения, а не как ошибки тестов.
- [ ] Выбор `model` обоснован.

## Упражнение 5. Цепочка из двух subagents  ·  ⏱ ~45 мин  ·  обязательное

**Цель:** провести фичу через цепочку «план → реализация → test-writer → code-reviewer», где основная сессия — оркестратор.
**Зачем:** так устроена реальная командная разработка: исполнитель, тестировщик и ревьюер — разные люди. Ты учишься разбивать работу на роли и контролировать передачу между ними.

**Шаги:**
1. Закоммить текущее состояние.
2. Включи plan mode (Shift+Tab) и дай задачу:
   ```
   Добавь в todo-app команду `search <текст>`: показывает задачи, в названии которых
   встречается текст (без учёта регистра). Сначала изучи, как устроены команды
   (можешь использовать Explore), и составь план. Запиши план в plan.md.
   ```
   Прочитай `plan.md`. Поправь, если нужно. Выйди из plan mode.
3. Одним сообщением запусти цепочку:
   ```
   Реализуй план из plan.md. Затем:
   1) используй subagent test-writer, чтобы покрыть команду search тестами;
   2) используй subagent code-reviewer для ревью всех изменений (git diff);
   3) покажи мне замечания ревьюера и исправь только «критично» и «важно».
   ```
4. Наблюдай и запиши в `chain-notes.md`:
   - какие агенты запускались и в каком порядке;
   - что каждый вернул (кратко) и как основная сессия использовала этот результат;
   - `/context` в конце;
   - нашёл ли ревьюер что-то, что пропустила основная сессия.
5. Проверь: `python todo.py search молоко` (или слово из своих задач), `python -m pytest -q`. Закоммить.
6. Ответь в заметках: что бы изменилось, если бы ты сделал всё одним сообщением без subagents? Стоило ли оно того на такой маленькой фиче?

**Что сдать на проверку:** коммит с фичей, `plan.md`, `chain-notes.md`.
**Критерии готовности:**
- [ ] Команда `search` работает, тесты на неё есть и проходят.
- [ ] В `chain-notes.md` описаны оба subagent и что передавалось между этапами.
- [ ] Есть рефлексия «стоило ли того» с аргументом (стоимость/качество).
- [ ] Перед изменениями был коммит (видно в `git log`).

## Упражнение 6 ⭐. Свой agent loop на Anthropic SDK  ·  ⏱ ~60 мин  ·  необязательное (платно)

**Цель:** запустить минимальный agent loop из `practice/agent-loop/` и расширить его третьим tool.
**Зачем:** после этого Claude Code перестаёт быть «магией»: ты увидишь, что агент — это ~50 строк цикла, а вся «умность» — в модели и в описаниях tools.

> ⚠️ Нужен API key с балансом на console.anthropic.com — это отдельно от подписки. Прочитай `practice/agent-loop/README.md` целиком. Ключ — только в переменную окружения, никогда в код и в чат.

**Шаги:**
1. Скопируй `practice/agent-loop/` в `~/claude-practice/agent-loop/`, создай venv, `pip install anthropic`, задай `ANTHROPIC_API_KEY` (см. README папки).
2. Запусти: `python agent.py "Что лежит в этой папке и о чём README.md?"`. Перепиши в `sdk-notes.md` трассу: шаги, tools, `tokens in` на каждом шаге. Почему `tokens in` растёт?
3. Добавь третий tool `search_text(pattern, path)` — ищет строку во всех `.py`/`.md` файлах папки и возвращает `файл:строка: текст`. Не забудь: описание в `TOOLS` + ветку в `run_tool` + ограничение `safe_path`.
4. Скопируй рядом `todo-app` (или запусти агент из его папки) и дай задачу, где `search_text` полезен: «Найди, где в проекте задаётся путь к todos.json». Вызвался ли новый tool? Если нет — улучши его `description` и повтори.
5. Поставь `MAX_TURNS = 2` и дай задачу, требующую больше шагов. Что произошло и зачем нужен этот предохранитель?

**Что сдать на проверку:** изменённый `agent.py`, `sdk-notes.md` с трассами и ответами.
**Критерии готовности:**
- [ ] `search_text` работает и не выходит за пределы рабочей папки.
- [ ] Модель вызвала новый tool без прямого указания «используй search_text».
- [ ] Объяснён рост `tokens in` и роль `MAX_TURNS`.
- [ ] API key не встречается ни в одном файле.
