> **Где выполнять:** в чате https://claude.ai (подойдёт бесплатный аккаунт). Claude Code пока не нужен.
> **Что понадобится из `practice/`:** `practice/texts/report.md` (упражнение 5) — открой его в любом текстовом редакторе или прямо в папке курса и скопируй текст.
> **Как сдавать:** результаты (таблицы, наблюдения) запиши в один файл, например `~/claude-practice/01-llm/notes.md`, или вставь в чат учителю. Папку `~/claude-practice` подробно создадим в модуле 02 — пока можно просто создать её в проводнике/Finder.

## Упражнение 1. Сколько влезает в context window  ·  ⏱ ~20 мин  ·  обязательное

**Цель:** научиться оценивать объём текста в tokens и прикидывать, что поместится в context window.
**Зачем:** почти все проблемы «Claude забыл / проигнорировал / ответил не по документу» связаны с объёмом контекста. Оценка «на салфетке» помогает заранее решить: вставить документ целиком, по частям или только нужный фрагмент.

**Шаги:**
1. Открой страницу https://docs.claude.com/en/docs/about-claude/models и найди размер context window модели, которой ты пользуешься (по умолчанию в claude.ai). Запиши число.
2. Выбери 3 типичных документа из своей работы (или возьми из `practice/texts/`): например, письмо, отчёт, договор. Для каждого узнай число символов (в Word: «Рецензирование → Статистика»; в Google Docs: «Инструменты → Статистика»; в VS Code — внизу справа при выделении текста).
3. Оцени число tokens по правилу из раздела 2 README: для английского ≈ символы / 4; для русского возьми диапазон ≈ символы / 3 … символы / 2 (точнее измерим в модуле 02).
4. Посчитай для каждого документа: сколько таких документов теоретически поместится в context window.
5. Спроси Claude: «Сколько примерно tokens в тексте ниже? Объясни, как ты оценил» — и вставь один из документов (обезличенный, если в нём есть данные клиентов — см. раздел 10 README). Сравни с собственной оценкой.
6. Сформулируй 2 вывода: какой из твоих документов «тяжёлый», и как бы ты работал с документом, который в окно **не** помещается.

**Что сдать на проверку:** таблица `документ | символов | оценка tokens (диапазон) | сколько поместится в окно` + оценка Claude + 2 вывода.

**Критерии готовности:**
- [ ] размер context window взят из документации, а не придуман
- [ ] расчёт для 3 документов с понятной арифметикой (диапазон, а не «точное» число)
- [ ] сравнение с оценкой Claude и объяснение расхождения
- [ ] вывод про документ, который не помещается, содержит конкретный приём (разбить на части, дать только нужный раздел, сначала резюме частей…)

## Упражнение 2. Один prompt — разные ответы  ·  ⏱ ~25 мин  ·  обязательное

**Цель:** увидеть недетерминированность своими глазами и понять, как уточнение prompt делает ответы стабильнее.
**Зачем:** если ты используешь Claude для повторяющейся работы (разметка писем, извлечение данных), разброс ответов — главный враг. Нужно понимать, откуда он берётся и чем управляется.

**Шаги:**
1. Отправь три prompt, **каждый 3 раза** (в новых чатах или кнопкой перегенерации ответа):
   - **A (творческий):** `Придумай 5 названий для внутренней рассылки отдела продаж.`
   - **B (оценочный, расплывчатый):** `Это письмо клиента позитивное или негативное? «Инженер приехал вовремя, но принтер так и не починил, хотя объяснил, что делать».`
   - **C (фактический):** `Сколько дней в високосном году и почему он так называется?`
2. Для каждого prompt запиши: что совпадало во всех трёх ответах, что отличалось (формулировки, порядок, количество, сам вывод).
3. Перепиши prompt B так, чтобы ответ был стабильным. Подсказка: задай фиксированные варианты ответа и формат («ответь одним словом из списка: …»), скажи, что делать, если письмо смешанное.
4. Отправь новую версию B 3 раза. Сравни разброс с исходной.

**Что сдать на проверку:** таблица `prompt | что совпало | что различалось` для A, B, C и новой B; текст новой версии B; 2–3 предложения: почему разброс у A, B и C разный.

**Критерии готовности:**
- [ ] каждый prompt отправлен 3 раза, наблюдения конкретные (не «ответы немного разные»)
- [ ] новая версия B ограничивает варианты ответа и учитывает смешанный случай
- [ ] объяснение связывает разброс с temperature/вероятностями и с тем, насколько однозначен вопрос

## Упражнение 3. Граница знаний  ·  ⏱ ~15 мин  ·  обязательное

**Цель:** проверить, как Claude ведёт себя на вопросах о событиях после knowledge cutoff, и как это исправляет поданный в context текст.
**Зачем:** самая коварная ошибка — не «я не знаю», а уверенный устаревший ответ. Важно чувствовать, где проходит граница, и уметь её обойти.

**Шаги:**
1. Спроси Claude: `Какая у тебя граница знаний (knowledge cutoff)? Какое сегодня число?` Сверь ответ про cutoff со страницей Models в документации.
2. Выбери событие **последних 2–4 недель**, о котором ты точно знаешь (новость отрасли, обновление программы, которой пользуешься, изменение в твоей компании, которое было опубликовано). Спроси о нём Claude без подсказок.
3. Запиши: Claude честно сказал, что не знает? Ответил о более старых событиях? Что-то придумал?
4. Открой новый чат, вставь короткую выдержку (3–5 предложений) об этом событии и задай тот же вопрос с пометкой «отвечай по тексту ниже».
5. Если в твоём аккаунте доступен веб-поиск, попробуй третий вариант — с поиском. Обрати внимание, ссылается ли ответ на источники.

**Что сдать на проверку:** вопрос; ответы в 2 (или 3) вариантах — кратко; вывод: какой способ ты будешь использовать для свежих данных и почему.

**Критерии готовности:**
- [ ] cutoff сверен с документацией
- [ ] описано поведение без контекста (не знает / устаревшее / выдумка)
- [ ] сравнение с ответом по поданному тексту
- [ ] вывод объясняет, почему поданный в context текст надёжнее «памяти» модели

## Упражнение 4. Поймай hallucination и защитись от неё  ·  ⏱ ~30 мин  ·  обязательное

**Цель:** спровоцировать правдоподобную выдумку, распознать её и проверить, какие формулировки prompt снижают риск.
**Зачем:** в работе ты будешь использовать ответы Claude в письмах, отчётах и решениях. Навык «где проверять» важнее, чем надежда, что модель не ошибётся.

**Шаги:**
1. Задай вопросы с подвохом (каждый — в новом чате):
   - про несуществующее понятие: `Объясни метод «обратной пирамиды Кастельского» в управлении проектами и приведи пример применения.`
   - с ложной предпосылкой: `Почему в 2019 году в России отменили летнее время в третий раз?`
   - с запросом источников: `Дай 3 ссылки на научные исследования о влиянии открытых офисов на продуктивность, с авторами и годом.`
2. Для каждого ответа определи: что правда, что выдумка, что неизвестно. **Проверь** ссылки и авторов — открой ссылки, найди статьи поиском.
3. Повтори первые два вопроса с добавкой: `Если ты не уверен, что такое понятие/событие существует, прямо скажи об этом и не додумывай.` Сравни ответы.
4. Работа с документом: скопируй разделы 4–5 из `practice/texts/report.md` и спроси: `По тексту ниже: сколько клиентов ушло из-за долгой работы поддержки? Приведи дословную цитату, на которой основан ответ. Если в тексте нет точного ответа — скажи об этом.` Проверь цитату по тексту.

**Что сдать на проверку:** таблица `вопрос | что ответил Claude (кратко) | правда/выдумка | как проверил`; сравнение ответов «до» и «после» разрешения сказать «не знаю»; ответ по документу с цитатой и твоей проверкой.

**Критерии готовности:**
- [ ] для каждого ответа указано, как именно проверено (а не «вроде правда»)
- [ ] ссылки из третьего вопроса реально открыты/найдены, результат записан
- [ ] есть сравнение «до/после» явного разрешения не знать
- [ ] в части с документом проверено, что цитата дословная, и учтено, что «7 упоминаний» ≠ «7 клиентов»

## Упражнение 5. Сравнение моделей  ·  ⏱ ~30 мин  ·  обязательное

**Цель:** на собственном опыте почувствовать разницу между более сильной и более быстрой моделью.
**Зачем:** выбор модели — это выбор между качеством, скоростью и стоимостью. Правильный выбор делается на своих задачах, а не по рекламе.

**Шаги:**
1. Посмотри, какие модели доступны в твоём аккаунте claude.ai (переключатель модели в окне чата). Если доступна только одна — выполни шаги 2–4 с ней, а сравнение с другой моделью сделаешь в модуле 02 командой `/model` в Claude Code (учитель напомнит).
2. **Задача-простая:** `Отнеси каждый отзыв к категории «доставка», «качество», «цена»: 1) Привезли на день позже. 2) Дороговато, но работает. 3) Сломался через неделю. 4) Курьер не позвонил. 5) У конкурентов дешевле на 20%.` Отправь в двух моделях.
3. **Задача-сложная:** вставь весь текст `practice/texts/report.md` и попроси: `Найди в отчёте утверждения, которые противоречат данным из таблиц этого же отчёта. Для каждого приведи цитату утверждения и цифры, которые ему противоречат.` Отправь в двух моделях.
4. Для каждой пары ответов запиши: время ответа (на глаз), правильность, полноту, стиль.

**Что сдать на проверку:** таблица `задача | модель | скорость | что нашла/как ответила | ошибки`; рекомендация из 2–3 предложений: какую модель ты бы взял для каждой задачи и почему.

**Критерии готовности:**
- [ ] обе задачи прогнаны (на двух моделях или одной — с пометкой)
- [ ] в сложной задаче указано, какие противоречия нашла каждая модель (сколько из реально существующих)
- [ ] рекомендация опирается на наблюдения, а не на «Opus всегда лучше»

## Упражнение 6. Память и приватность  ·  ⏱ ~20 мин  ·  обязательное

**Цель:** убедиться, что модель stateless, и отработать обезличивание данных перед отправкой.
**Зачем:** две частые ошибки новичка — надеяться, что Claude «запомнил» договорённости из прошлого чата, и вставлять в чат реальные данные клиентов.

**Шаги:**
1. **Память.** В новом чате напиши: `Запомни: в моих отчётах суммы всегда в тысячах рублей, без копеек.` Затем открой **ещё один** новый чат и спроси: `В каком формате я указываю суммы в отчётах?` Запиши, что произошло. Подумай, почему.
   - Если в твоём аккаунте есть Projects: создай проект, впиши это правило в инструкции проекта и проверь в двух разных чатах внутри проекта.
2. **Обезличивание.** Ниже — письмо с персональными данными (все данные вымышленные, но представь, что они настоящие). Перепиши его так, чтобы в нём не осталось персональных данных, но Claude всё ещё мог помочь с ответом:

   ```text
   Здравствуйте! Меня зовут Петрова Анастасия Игоревна, договор № 77-1405 от 12.03.2025.
   Мой телефон +7 900 000-12-34, почта a.petrova@example.com. С моей карты 4000 0000 0000 0002
   дважды списали 4 900 ₽ за сервисное обслуживание за сентябрь. Прошу вернуть лишнее
   списание и ответить, почему так произошло.
   ```
3. Отправь Claude обезличенную версию с просьбой подготовить вежливый ответ клиенту от имени отдела поддержки.
4. Отметь: потребовались ли Claude удалённые данные, чтобы написать хороший ответ? Какие данные ты оставил и почему (например, сумму)?

**Что сдать на проверку:** что произошло в части «Память» и объяснение; обезличенный текст письма; ответ Claude; 2–3 предложения о том, что удалено, что оставлено и почему.

**Критерии готовности:**
- [ ] объяснено, почему второй чат не знает правила (stateless, история не передаётся), и как это решает Projects/файл с инструкциями
- [ ] в обезличенном письме нет ФИО, телефона, почты, номера карты и договора — вместо них заглушки
- [ ] сохранено то, что нужно для ответа (суть проблемы, сумма, период)
- [ ] ответ Claude можно отправить, подставив данные обратно

## Упражнение 7. ⭐ Ловушки tokenization  ·  ⏱ ~30 мин  ·  со звёздочкой

**Цель:** найти задачи, на которых модель ошибается из-за того, что видит tokens, а не буквы и цифры, и подобрать обходной путь.
**Зачем:** понимание *механизма* ошибки позволяет заранее выбирать правильный способ решения (код, пошаговость) вместо того, чтобы удивляться «как он мог ошибиться в таком простом».

**Шаги:**
1. Придумай или возьми 5 задач, где важны отдельные символы или точная арифметика. Примеры:
   - `Сколько букв «о» в слове «обороноспособность»?`
   - `Напиши слово «перпендикуляр» задом наперёд.`
   - `Сколько будет 48 372 × 9 617?`
   - `Отсортируй по алфавиту: ёж, ель, еда, ёлка, эхо.`
   - `Какое пятое слово в этом предложении: «…»?`
2. Задай каждую задачу «в лоб», в отдельном чате. Проверь ответ сам (посчитай вручную или калькулятором).
3. Для задач, где была ошибка (или ответ нестабилен при перегенерации), попробуй два обходных пути:
   - **пошагово:** `Сначала выпиши слово по одной букве через пробел с номерами, потом посчитай`;
   - **кодом:** `Напиши короткий код на Python, который это вычисляет, и покажи результат` (если в твоём аккаунте Claude может выполнять код — он выполнит; если нет — запустишь код сам позже, в модуле 05).
4. Объясни для каждой ошибки, почему она связана с tokenization или с тем, что модель «считает в уме».

**Что сдать на проверку:** таблица `задача | ответ «в лоб» (верно?) | пошагово (верно?) | кодом (верно?)`; объяснение механизма для 2–3 ошибок; твоё правило: «когда я прошу Claude о …, я сразу прошу …».

**Критерии готовности:**
- [ ] 5 задач, ответы проверены независимо
- [ ] опробованы оба обходных пути хотя бы для двух задач
- [ ] объяснение опирается на tokens (буквы склеены в кусочки, числа разбиты на части), а не на «модель глупая»
- [ ] сформулировано практическое правило
