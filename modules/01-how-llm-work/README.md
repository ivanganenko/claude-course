## 1. Что такое LLM: предсказание следующего token

**LLM** (Large Language Model, большая языковая модель) — программа, обученная на огромном объёме текста продолжать текст. Claude — это LLM, которую делает компания Anthropic.

Главное, что нужно запомнить: модель **генерирует ответ по кусочку**. На каждом шаге она смотрит на весь текст, который уже есть (твой вопрос + то, что она успела написать), и оценивает, какой кусочек вероятнее всего должен идти следующим. Выбирает один, дописывает — и повторяет, пока ответ не закончится.

Пример. Ты пишешь: «Столица Франции — …». Модель «видит», что после такого начала с огромной вероятностью идёт «Париж». Если ты напишешь «Расскажи сказку про кота, который…» — вариантов продолжения много, и модель выберет один из правдоподобных.

Что из этого следует на практике:

| Свойство | Что это значит для тебя |
|----------|------------------------|
| Модель продолжает текст, а не «ищет в базе» | ответ звучит гладко, даже если он неверный |
| Каждый следующий кусочек зависит от предыдущих | если начало ответа ушло не туда, модель продолжит в ту же сторону |
| Всё, что модель «знает» о задаче, — это текст перед ней | чем точнее ты описал задачу, тем лучше ответ |

После обучения на текстах модель дополнительно обучают быть полезным ассистентом: следовать инструкциям, отказываться от вредного, признавать неуверенность. Поэтому Claude не просто «продолжает фразу», а отвечает на вопрос. Но механизм под капотом тот же — по кусочку.

> **Почему так?** Предсказание следующего кусочка — простая задача, которую можно масштабировать на триллионы слов текста. Из этого простого обучения возникают сложные умения: перевод, рассуждение, код. Цена — модель оптимизирована на *правдоподобие*, а не на *истинность*. Отсюда растут почти все ограничения, о которых пойдёт речь дальше.

## 2. Tokens и tokenization

Модель работает не с буквами и не со словами, а с **tokens** (токены — кусочки текста: слово, часть слова, знак препинания, пробел). Разбиение текста на tokens называется **tokenization**.

Пример того, как это *может* выглядеть (реальное разбиение зависит от модели):

```text
"Привет, мир!"        →  ["При", "вет", ",", " мир", "!"]
"unbelievable"        →  ["un", "believ", "able"]
"2026-10-04"          →  ["202", "6", "-", "10", "-", "04"]
```

Почему это важно знать:

1. **Всё считается в tokens.** Размер context window, лимиты, стоимость в API — всё в tokens, а не в словах или страницах.
2. **Разные языки «стоят» по-разному.** Английский текст обычно делится на меньшее число tokens, чем русский текст того же смысла. Для грубой оценки: в английском ≈ 4 символа на token (≈ ¾ слова), в русском — заметно меньше символов на token. Точные цифры зависят от модели — в модуле 02 ты сможешь измерить это сам командой `/context`.
3. **Модель плохо видит отдельные буквы.** Задачи «сколько букв "р" в слове "переворот"» или «напиши слово задом наперёд» неожиданно трудны: модель видит не буквы, а кусочки. Такие задачи лучше решать кодом (Claude может написать и выполнить короткий скрипт — в Claude Code это обычное дело).

> **Почему так?** Работать с отдельными буквами — слишком долго (текст становится очень длинным), работать с целыми словами — слишком много вариантов (все формы всех слов всех языков). Tokens — компромисс: частые слова и части слов становятся одним token, редкие собираются из нескольких.

## 3. Context window

**Context window** (окно контекста — сколько текста модель «видит» за раз) — максимальный объём tokens, который модель может учитывать одновременно. В него входит **всё**:

- инструкции, которые продукт добавляет «за кадром» (system prompt — служебные инструкции для модели);
- вся история текущего разговора: твои сообщения и ответы Claude;
- вложенные файлы, вставленный текст, результаты инструментов;
- ответ, который модель пишет прямо сейчас.

У современных моделей Claude context window — порядка сотен тысяч tokens. Это сотни страниц текста. Точные значения для каждой модели — на странице [Models overview](https://docs.claude.com/en/docs/about-claude/models). Отдельно есть лимит на длину *одного ответа* (max output tokens) — он намного меньше окна.

Что происходит, когда окно заполняется? Зависит от продукта: где-то старая часть разговора сжимается или отбрасывается, где-то вы получите сообщение, что разговор слишком длинный и пора начать новый. В Claude Code есть явные команды для этого (`/compact`, `/clear`) — разберём в модуле 04.

Важная мысль: **«влезает» не значит «хорошо работает».** Даже если документ помещается в окно, чем больше в контексте лишнего, тем легче модели упустить важное. Длинный разговор с десятком смен темы обычно даёт худшие ответы, чем короткий и сфокусированный.

Оценка «на салфетке»:

| Что | Примерно |
|-----|----------|
| 1 страница русского текста (≈ 1 800 символов) | порядка 500–1 000 tokens |
| Письмо на 5 абзацев | несколько сотен tokens |
| Договор на 30 страниц | десятки тысяч tokens |
| Книга на 300 страниц | сотни тысяч tokens — на грани окна или больше |

Цифры приблизительные — их задача дать порядок величины, а не точный ответ.

> **Почему так?** Модель на каждом шаге учитывает весь контекст сразу — это и даёт ей «понимание» связей между далёкими частями текста. Но вычисления растут вместе с длиной контекста, поэтому окно не бесконечно. Компромисс для тебя: давай модели всё *нужное*, но не всё *подряд*.

## 4. Temperature и недетерминированность

Вернёмся к выбору следующего token. Модель не просто берёт самый вероятный вариант — она **выбирает случайно, с учётом вероятностей**. Параметр, который управляет степенью случайности, называется **temperature**:

- низкая temperature → модель почти всегда выбирает самые вероятные варианты → ответы стабильнее и «суше»;
- высокая temperature → чаще выбираются менее вероятные варианты → ответы разнообразнее, но выше риск странностей.

В API temperature можно задать явно. В чате (claude.ai) и в Claude Code ты её обычно не настраиваешь — продукт выбирает за тебя.

Следствие: **один и тот же prompt даёт разные ответы.** Факты и смысл обычно совпадают, формулировки, порядок и детали — нет. Иногда отличается и содержание: в одном ответе пять пунктов, в другом шесть; в одном модель заметила подвох, в другом — нет.

Что с этим делать:

- для творческих задач (идеи, варианты заголовков) это плюс — попроси несколько вариантов или перегенерируй ответ;
- для задач, где важна стабильность (классификация, извлечение данных), — уточняй формат, давай примеры (модуль 03) и **проверяй**;
- если ответ на важный вопрос меняется от раза к разу — это сигнал, что модель не уверена или prompt допускает разные трактовки.

> **Почему так?** Если всегда выбирать самый вероятный token, текст получается однообразным и иногда «зацикливается» на повторах. Немного случайности делает речь естественнее. Цена — отсутствие гарантии одинакового ответа, поэтому серьёзные процессы строят на проверке результата, а не на надежде, что модель ответит «как в прошлый раз».

## 5. Knowledge cutoff

Модель обучают на текстах, собранных до определённой даты. Эта дата называется **knowledge cutoff** (граница знаний). О событиях после неё модель «из головы» не знает ничего. Дата своя у каждой модели — смотри страницу Models в документации.

Типичные ловушки:

- ты спрашиваешь о новой версии программы, а модель уверенно описывает старую;
- модель не знает о недавних изменениях закона, цен, курсов, руководства компании;
- модель может даже не знать, какое сегодня число, если продукт ей этого не сообщил.

Как обходить:

1. **Дай актуальные данные сам** — вставь текст, приложи файл, дай ссылку на выдержку. Тогда модель работает с твоим источником, а не с памятью.
2. **Используй поиск, если продукт его поддерживает.** Если в продукте включён веб-поиск, Claude может найти свежие источники и ответить по ним — проверь, что ответ ссылается на источники.
3. **Спрашивай о стабильных вещах** — принципы, методы, объяснения — там cutoff почти не мешает.

> **Почему так?** Переобучать большую модель — долго и дорого, поэтому её знания «заморожены» на момент обучения. Свежие данные дешевле подать в context (вставить или найти поиском), чем ждать новую модель. Этот же принцип — «дай модели нужные данные в контексте» — лежит в основе Projects, MCP и всего, что ты будешь делать в курсе.

## 6. Hallucinations: почему модель уверенно ошибается

**Hallucination** (галлюцинация) — правдоподобный, но неверный ответ: несуществующая цитата, выдуманная статья закона, функция библиотеки, которой нет, неверная цифра.

Почему это происходит:

| Причина | Пример |
|---------|--------|
| Модель оптимизирована на правдоподобие, а не на истину | «цитата великого человека», которая звучит в его стиле, но он её не говорил |
| Мало данных о теме при обучении | редкая книга, маленькая компания, узкий термин — модель «достраивает» |
| Вопрос уже содержит ложную предпосылку | «Почему Эйфелеву башню перенесли в Лион?» — модель может начать объяснять |
| Нужна точность, которую модель «на глаз» не даёт | подсчёты по большой таблице, точные даты, номера, ссылки |
| Событие после knowledge cutoff | модель придумывает «последнюю версию» |

Как снизить риск:

- **Дай источник и попроси отвечать только по нему.** «Отвечай только на основании документа ниже. Если ответа в нём нет — так и скажи».
- **Разреши сказать «не знаю».** Модели обучены быть полезными; явное разрешение признать незнание заметно снижает выдумки (подробнее — в модуле 03).
- **Проси цитаты.** «Приведи дословную цитату из документа, на которой основан вывод». Цитату легко проверить поиском по тексту.
- **Проверяй критичное.** Цифры, имена, даты, ссылки, юридические и медицинские утверждения — сверяй с первоисточником. Ссылки открывай.
- **Для расчётов используй код.** Попроси Claude посчитать с помощью скрипта, а не «в уме».

Признаки, при которых стоит насторожиться: очень конкретные детали по малоизвестной теме (точные номера страниц, ISBN, проценты), ссылки, которые ты не можешь открыть, ответ меняется при перегенерации.

> **Почему так?** У модели нет отдельного «модуля правды», который проверял бы ответ перед выдачей. Она генерирует то, что статистически похоже на хороший ответ. Поэтому лучшая стратегия — не надеяться, что модель «перестанет врать», а строить работу так, чтобы ошибку было легко заметить: источники, цитаты, проверки, тесты.

## 7. Модели семейства Claude: Opus, Sonnet, Haiku

Anthropic выпускает модели нескольких «размеров». Названия поколений и номера версий меняются, но линейка устроена одинаково:

| Модель | Сильная сторона | Компромисс | Когда брать |
|--------|-----------------|------------|-------------|
| **Opus** | самая сильная: сложные рассуждения, большие задачи, тонкие нюансы | медленнее и дороже | сложный анализ, архитектура, трудный баг, ответственный текст |
| **Sonnet** | баланс качества и скорости | — | большинство повседневных задач, работа с кодом |
| **Haiku** | самая быстрая и дешёвая | слабее на сложных задачах | простые массовые задачи: классификация, короткие резюме, извлечение полей |

Актуальный список моделей, их возможности, context window и knowledge cutoff — на странице [Models overview](https://docs.claude.com/en/docs/about-claude/models). Конкретные версии в курсе намеренно не указаны: они устаревают быстрее, чем курс.

Практические правила:

- начинай с модели по умолчанию в твоём продукте — обычно этого достаточно;
- если ответ поверхностный или модель путается в сложной задаче — попробуй более сильную;
- если задача простая и её нужно делать много раз — попробуй более быструю и сравни качество на нескольких примерах;
- в Claude Code модель переключается командой `/model` (алиасы `opus`, `sonnet`, `haiku`) — это будет в модуле 02.

> **Почему так?** Более крупная модель лучше рассуждает, но каждый token требует больше вычислений — отсюда скорость и цена. Одной «лучшей во всём» модели не бывает: ты выбираешь точку на кривой «качество — скорость — стоимость» под конкретную задачу.

## 8. Продукты: где работать с Claude

| Продукт | Что это | Когда использовать |
|---------|---------|--------------------|
| **claude.ai** (веб и мобильное приложение) | чат с Claude: текст, файлы, изображения | вопросы, тексты, разбор документов, мозговой штурм |
| **Projects в claude.ai** | папка для группы чатов с общими инструкциями и файлами | регулярная работа над одной темой: «отчёты отдела», «клиент X» |
| **Claude Desktop** | приложение для Windows/macOS: тот же чат, плюс можно подключать локальные инструменты (MCP) | когда хочется чат на компьютере и доступ к локальным данным через инструменты |
| **Claude Code** | агент в терминале (и в IDE): читает и меняет файлы, выполняет команды | работа с файлами и кодом, автоматизация, всё, что дальше в курсе |
| **API** | программный доступ для разработчиков, оплата за tokens | встроить Claude в свою программу или процесс |

Как выбрать: если результат — **ответ в чате**, тебе достаточно claude.ai. Если результат — **изменённые файлы, работающий скрипт, обработанная папка документов** — нужен Claude Code. API — когда ты пишешь программу, которая сама обращается к Claude.

Набор функций в продуктах и тарифах меняется (например, веб-поиск, memory, доступные модели). Актуальное — в документации и в настройках твоего аккаунта.

> **Почему так?** Модель одна и та же, разница — в том, что продукт даёт ей *видеть* и *делать*. В чате Claude видит только то, что ты вставил, и может только ответить текстом. В Claude Code у него есть tools (инструменты): чтение файлов, правка, запуск команд. Больше возможностей — больше пользы, но и больше ответственности за то, что ты разрешаешь.

## 9. Что Claude «видит» и «помнит»

Модель **stateless** (без состояния): между запросами у неё нет собственной памяти. Ощущение, что Claude «помнит» начало разговора, создаёт продукт: при каждом твоём сообщении он заново отправляет модели всю историю этого чата.

Отсюда:

- **Новый чат = чистый лист.** Claude не помнит, что вы обсуждали вчера в другом чате (если не включены специальные функции — см. ниже).
- **Внутри одного чата помнит всё, что влезает в context window** — и именно поэтому длинные чаты «тяжелеют».
- **Способы дать «память»** — это всегда способы автоматически положить нужный текст в context:
  - *Projects* в claude.ai — инструкции и файлы проекта подставляются в каждый чат проекта;
  - функция *memory* в claude.ai (в некоторых тарифах) — Claude может учитывать сведения из прошлых разговоров; проверь настройки своего аккаунта и документацию;
  - в Claude Code — файлы `CLAUDE.md` (модуль 06), которые читаются в начале каждой сессии.

Хорошая привычка: если что-то важно для следующего разговора — **запиши это в файл или в инструкции проекта**, а не надейся, что модель запомнит. (Агент-преподаватель этого курса работает так же: всё о твоём прогрессе он хранит в `PROGRESS.md`.)

> **Почему так?** Хранить «память» внутри модели для каждого пользователя невозможно — модель одна на всех. Гораздо проще и прозрачнее хранить память снаружи, в виде текста, и подставлять его в context. Плюс для тебя: эту память можно прочитать, исправить и удалить.

## 10. Privacy-гигиена: что нельзя вставлять в чат

Всё, что ты отправляешь в Claude, уходит на серверы провайдера и становится частью context. Даже если провайдер защищает данные, правило простое: **не отправляй то, что не имеешь права или не должен передавать.**

Не вставляй:

- пароли, API keys, токены доступа, ключи шифрования, содержимое `.env`-файлов;
- персональные данные клиентов и сотрудников: ФИО вместе с контактами, паспортные данные, номера карт и счетов, медицинские сведения;
- коммерческую тайну и документы под NDA, если политика компании этого не разрешает.

Что делать вместо этого:

| Ситуация | Решение |
|----------|---------|
| Нужно разобрать письмо клиента | замени имя, компанию, телефон, адрес на заглушки: `[КЛИЕНТ]`, `[ТЕЛЕФОН]` |
| Нужно проанализировать таблицу с клиентами | оставь только нужные столбцы, ID вместо имён, или сгенерируй похожие тестовые данные |
| Скрипту нужен API key | храни его в переменной окружения, а не в тексте prompt или в коде (подробнее — в модулях 08–10) |
| Не уверен, можно ли | уточни политику компании по работе с AI-инструментами — у организации могут быть свои правила и свой корпоративный тариф |

Отдельный риск — **случайная утечка в Claude Code**: агент может прочитать файл с секретами, если ты разрешишь. В модуле 10 ты научишься запрещать это настройками.

> **Почему так?** Утечку нельзя «откатить»: отправленный текст уже покинул твой компьютер. Обезличивание стоит минуту, а качество ответа почти никогда от него не зависит — Claude не нужно настоящее имя клиента, чтобы помочь ответить на его жалобу.

## Шпаргалка

| Понятие | Запомни одной фразой | Что делать |
|---------|---------------------|------------|
| Next-token prediction | модель пишет ответ по кусочку, выбирая правдоподобное продолжение | формулируй задачу точно — модель «знает» только текст перед ней |
| Token | кусочек текста; всё считается в tokens | оценивай объём: страница ≈ сотни tokens |
| Context window | всё, что модель видит за раз, включая историю и ответ | давай нужное, а не всё подряд; длинные чаты начинай заново |
| Temperature | степень случайности выбора | для стабильности — точный формат и примеры; для идей — несколько вариантов |
| Knowledge cutoff | после этой даты модель ничего не знает | давай свежие данные сам или используй поиск |
| Hallucination | правдоподобная выдумка | источник + «скажи, если не знаешь» + цитаты + проверка |
| Opus / Sonnet / Haiku | сила / баланс / скорость и цена | начни с модели по умолчанию, меняй осознанно |
| Stateless | память = текст, который подставили в context | важное записывай в файлы и инструкции |
| Privacy | отправленное не вернуть | заглушки вместо персональных данных, секреты — никогда |

## Глоссарий

| Термин | Что значит |
|--------|-----------|
| LLM (Large Language Model) | большая языковая модель: программа, обученная продолжать текст |
| prompt | текст запроса к модели: инструкция, вопрос, данные |
| token | минимальный кусочек текста, с которым работает модель |
| tokenization | разбиение текста на tokens |
| context window | максимальный объём tokens, который модель учитывает за раз |
| system prompt | служебные инструкции, которые продукт или разработчик даёт модели до разговора |
| max output tokens | лимит длины одного ответа модели |
| temperature | параметр случайности при выборе следующего token |
| knowledge cutoff | дата, до которой собраны данные для обучения модели |
| hallucination | уверенный, правдоподобный, но неверный ответ |
| stateless | без собственной памяти между запросами |
| Projects | пространство в claude.ai с общими инструкциями и файлами для группы чатов |
| tool | инструмент, который модель может вызвать: прочитать файл, выполнить команду, поискать в вебе |
| API | программный интерфейс для доступа к модели из своих программ |
| PII (personally identifiable information) | персональные данные, по которым можно определить человека |
