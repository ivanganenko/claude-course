# Модуль 03 — практика

> **Где выполнять:** в Claude Code, в папке `~/claude-practice/03-prompting` (отдельное окно терминала, не окно учителя). Упражнение 1 можно делать и в claude.ai.
> **Что скопировать из `practice/`:** все файлы из `practice/texts/`:
> - PowerShell: `mkdir ~\claude-practice\03-prompting` и `Copy-Item ~\claude-course\practice\texts\* ~\claude-practice\03-prompting\`
> - bash: `mkdir -p ~/claude-practice/03-prompting` и `cp ~/claude-course/practice/texts/* ~/claude-practice/03-prompting/`
>
> (если курс лежит не в `~/claude-course` — подставь свой путь)
> **Как сдавать:** каждый результат — отдельный файл в `~/claude-practice/03-prompting/`. Свои prompts тоже сохраняй в файлы: учитель будет смотреть именно на них.
> **Важно:** между вариантами одного эксперимента делай `/clear` — иначе второй вариант «увидит» первый ответ и сравнение будет нечестным.

## Упражнение 1. Перепиши 5 плохих prompts  ·  ⏱ ~40 мин  ·  обязательное

**Цель:** научиться видеть, чего не хватает в prompt, и исправлять это.
**Зачем:** большая часть «Claude ответил не то» — это «я не сказал, что мне нужно». Навык диагностики prompt окупается каждый день.

**Шаги:**
1. Открой `bad-prompts.md`. Для каждого из 5 prompts прочитай ситуацию и сам prompt.
2. Для каждого запиши **диагноз** по чек-листу из шпаргалки README (цель, контекст, формат, разделение данных, примеры, критерии, лишнее): какие пункты провалены и почему.
3. Перепиши каждый prompt. Опирайся только на факты из ситуации — не выдумывай новые условия. Где фактов не хватает, оставь заглушку `[уточнить: …]`.
4. Для **двух** prompts на выбор (рекомендуем 1 и 4) проведи эксперимент в Claude Code: отправь исходную версию, сохрани ответ; `/clear`; отправь свою версию, сохрани ответ. (Prompts ссылаются на файлы — используй `@report.md`, `@sales.csv`.)
5. Сравни ответы: что изменилось и почему.

**Что сдать на проверку:** файл `ex1-rewrites.md`: для каждого prompt — диагноз, новая версия; для двух — краткое сравнение ответов «до/после».

**Критерии готовности:**
- [ ] у всех 5 prompts есть диагноз с объяснением, *почему* это мешает
- [ ] новые версии содержат цель, аудиторию/контекст и формат результата
- [ ] в prompt 3 данные отделены от инструкций (тег или `@meeting-notes.txt`), а «кто молодец» убран или вынесен отдельно с объяснением
- [ ] в prompt 5 задача разбита или сужена, и нет требования «посчитать бюджет» без данных
- [ ] для двух prompts есть сравнение реальных ответов

## Упражнение 2. Из хаоса заметок — в таблицу  ·  ⏱ ~30 мин  ·  обязательное

**Цель:** извлечь структурированные данные из хаотичного текста с помощью XML-тегов, явных правил и формата.
**Зачем:** «разобрать заметки/переписку/протокол в таблицу задач» — одна из самых частых офисных задач для Claude. И именно здесь важны правила для неоднозначностей: иначе модель тихо «додумает» срок или ответственного.

**Шаги:**
1. Отправь простой prompt: `Сделай таблицу задач из @meeting-notes.txt`. Сохрани ответ в `ex2-v1.md` (попроси Claude записать его в файл или скопируй).
2. `/clear`. Напиши свою версию prompt, где:
   - заметки отделены от инструкций (тег `<notes>` со вставленным текстом или `@meeting-notes.txt`);
   - перечислены колонки таблицы;
   - есть правила: что делать, если срок или ответственный не указан; если срок менялся по ходу встречи; если формулировка размыта («до пятницы» — какой?);
   - отдельно — решения встречи и открытые вопросы;
   - результат записывается в файл `meeting-tasks.md`.
3. Сохрани свой prompt в `ex2-prompt.md`, отправь его, проверь `meeting-tasks.md` **по исходным заметкам** — каждую строку.
4. Если нашёл ошибку — улучши prompt (не правь результат руками!) и повтори.

**Что сдать на проверку:** `ex2-v1.md`, `ex2-prompt.md` (финальная версия), `meeting-tasks.md`, 2–3 предложения: чем v1 хуже финальной версии и какие правила понадобились.

**Критерии готовности:**
- [ ] в `meeting-tasks.md` все задачи из заметок, включая «Марина посмотрит бюджет»
- [ ] срок текстов Светы — 20 октября (последний вариант), изменение отмечено
- [ ] неоднозначности («до пятницы», «на этой неделе», FAQ «вроде да») помечены, а не «додуманы»
- [ ] есть разделы «Решения» и «Открытые вопросы»
- [ ] в prompt инструкции и данные разделены

## Упражнение 3. Few-shot классификация писем  ·  ⏱ ~35 мин  ·  обязательное

**Цель:** сравнить zero-shot и few-shot классификацию и увидеть, как примеры стабилизируют результат на пограничных случаях.
**Зачем:** разметка входящих писем, обращений, отзывов — массовая задача, где важна стабильность. Примеры — самый надёжный способ объяснить модели границы категорий.

**Шаги:**
1. Категории: `billing` (счета, оплата), `sales` (запрос на покупку/предложение), `tech` (неисправность, настройка), `complaint` (недовольство сервисом/качеством, требование замены или компенсации, угроза уйти), `cancel` (расторжение договора), `feedback` (благодарность, отзыв). Срочность: `high` / `normal`.
2. **Zero-shot.** Напиши prompt с категориями и форматом вывода — CSV `номер;категория;срочность;суть` — без примеров. Классифицируй все 10 писем из `@emails.txt`. Сохрани результат в `ex3-zero-shot.csv`. `/clear` и повтори ещё раз → `ex3-zero-shot-2.csv`.
3. **Few-shot.** Добавь в prompt 3–4 примера в тегах `<example>`. Примеры придумай **сам** (не бери письма из `emails.txt` — иначе проверка нечестная). Хотя бы 2 примера — на пограничные случаи: «техническая проблема + недовольство», «вопрос + желание купить».
4. Прогони few-shot версию дважды (с `/clear` между прогонами) → `ex3-few-shot.csv`, `ex3-few-shot-2.csv`.
5. Сравни 4 файла: в каких письмах категория менялась между прогонами? Где zero-shot и few-shot разошлись? Можешь попросить Claude сравнить файлы, но вывод сформулируй сам.

**Что сдать на проверку:** 4 CSV-файла; prompt few-shot версии в `ex3-prompt.md`; таблица-сравнение по письмам, где были расхождения, и вывод (3–5 предложений) в `ex3-notes.md`.

**Критерии готовности:**
- [ ] формат CSV одинаковый во всех файлах, без лишнего текста
- [ ] примеры в few-shot придуманы самостоятельно, включают пограничные случаи
- [ ] найдены и разобраны расхождения (особенно письма 3, 6, 10)
- [ ] вывод объясняет, *почему* примеры уменьшают разброс

## Упражнение 4. A/B-сравнение версий prompt  ·  ⏱ ~35 мин  ·  обязательное

**Цель:** на одной задаче измерить, что дают контекст, формат и просьба рассуждать (или посчитать кодом).
**Зачем:** улучшать prompts «на глаз» ненадёжно. Привычка сравнивать версии на одних и тех же данных — основа работы с LLM.

**Шаги:**
1. Задача: подготовить материал к встрече руководителя отдела продаж с менеджерами по `@sales.csv` (продажи за сентябрь).
2. **v1** — `Проанализируй @sales.csv.` → сохрани ответ в `ex4-v1.md`.
3. `/clear`. **v2** — добавь цель, аудиторию и формат (например: 3–4 вывода с цифрами, таблица выручки по менеджерам и регионам, один вопрос для обсуждения). → `ex4-v2.md`.
4. `/clear`. **v3** — v2 + «сначала посчитай агрегаты с помощью Python-скрипта и покажи результаты, затем делай выводы; отметь аномалии в данных (возвраты, пустые значения)». → `ex4-v3.md`. (Если Python не установлен — попроси рассуждать по шагам в `<thinking>`, а цифры проверь в Excel/Google Sheets.)
5. **Проверь цифры** в v1 и v2: совпадают ли суммы выручки по регионам и менеджерам с v3 (или с твоим подсчётом в таблице)?
6. Заполни сравнение.

**Что сдать на проверку:** `ex4-v1.md`, `ex4-v2.md`, `ex4-v3.md`; тексты трёх prompts; таблица в `ex4-compare.md`: `версия | полезно для встречи? | цифры верны? | заметил аномалии? | длина`, и вывод.

**Критерии готовности:**
- [ ] три версии прогнаны на одних данных с `/clear` между ними
- [ ] цифры проверены независимо (скрипт или таблица), ошибки отмечены
- [ ] отмечено, нашла ли каждая версия возврат (отрицательное количество) и строку без менеджера
- [ ] вывод: что дал каждый добавленный элемент prompt

## Упражнение 5. Право сказать «не знаю»  ·  ⏱ ~25 мин  ·  обязательное

**Цель:** проверить, как инструкции «только по источнику» и «если нет данных — скажи» влияют на выдумки.
**Зачем:** в рабочих документах «уверенно неправильный» ответ опаснее отсутствия ответа. Нужно уметь писать prompts, которые честно показывают границы данных.

**Шаги:**
1. Вопросы к `report.md`:
   1. На сколько процентов выросла выручка в III квартале?
   2. Сколько договоров «Сервис Премиум» заключено за квартал?
   3. Какая выручка была в регионе «Запад» в сентябре?
   4. Почему уволились менеджеры отдела продаж?
   5. Во сколько рублей обошёлся компании сбой 14 августа?
   6. Почему компания закрыла офис в регионе «Юг»?
   7. Какой доле обращений клиентов «Премиум» ответили в течение 2 часов?
2. **Вариант A:** `Ответь на вопросы по @report.md:` + список. Сохрани → `ex5-a.md`.
3. `/clear`. **Вариант B:** свой prompt с тремя элементами из README (раздел 9): только по документу; явная фраза для случая «нет данных»; дословная цитата к каждому ответу. → `ex5-b.md`.
4. Сам определи правильные ответы по отчёту и оцени оба варианта: верно / выдумка / пропустил подвох.

**Что сдать на проверку:** `ex5-a.md`, `ex5-b.md`, prompt варианта B, таблица оценки `вопрос | правильный ответ | A | B` в `ex5-score.md`.

**Критерии готовности:**
- [ ] в варианте B есть все три элемента (источник, фраза «нет данных», цитаты)
- [ ] правильные ответы определены самостоятельно по тексту отчёта
- [ ] замечен подвох в вопросе 1 (в отчёте две разные цифры роста) и ложная предпосылка в вопросе 6
- [ ] вывод: какие ошибки устранил вариант B, какие — нет

## Упражнение 6. Шаблон prompt для своей рабочей задачи  ·  ⏱ ~40 мин  ·  обязательное

**Цель:** собрать переиспользуемый шаблон prompt для задачи, которую ты реально делаешь на работе.
**Зачем:** это первый кирпич твоей личной «библиотеки» (модуль 04) и будущих skills (модуль 07). Шаблон превращает удачный prompt в повторяемый процесс.

**Шаги:**
1. Выбери повторяющуюся задачу из своей работы: ответы на типовые письма, еженедельный отчёт, протокол встречи, проверка документа, описание задачи для подрядчика…
2. Создай папку `prompts/` и файл `prompts/<короткое-имя>.md`. В нём:
   - заголовок и 1–2 предложения: для чего шаблон и когда его использовать;
   - сам шаблон по структуре из README (раздел 10): роль (если нужна), задача и цель, контекст и ограничения с причинами, примеры (если нужны), место для данных `{{...}}`, правило для нехватки данных, формат результата;
   - раздел «Как использовать»: что подставить, где взять данные.
3. Подготовь **обезличенные** тестовые данные (или придумай похожие) и прогони шаблон в Claude Code.
4. Оцени результат по чек-листу из шпаргалки. Улучши шаблон хотя бы один раз и прогони снова.
5. В конце файла добавь раздел «История версий»: что изменил и почему.

**Что сдать на проверку:** `prompts/<имя>.md` с шаблоном, инструкцией и историей версий; результаты двух прогонов (`ex6-run1.md`, `ex6-run2.md`).

**Критерии готовности:**
- [ ] задача реальная и повторяющаяся (не учебная)
- [ ] шаблон содержит цель, контекст, формат и место для данных; данные отделены от инструкций
- [ ] в тестовых данных нет реальных персональных данных и секретов
- [ ] есть минимум одна итерация улучшения с объяснением «почему»

## Упражнение 7. ⭐ Мини-конвейер: письма → JSON  ·  ⏱ ~45 мин  ·  со звёздочкой

**Цель:** написать один prompt, который превращает все письма в машиночитаемый JSON с черновиками ответов, и проверить результат автоматически.
**Зачем:** когда результат Claude читает не человек, а программа (таблица, CRM, скрипт), формат должен быть идеальным. Это тренирует строгий формат, few-shot и правила для неизвестных значений.

**Шаги:**
1. Напиши prompt, который по `@emails.txt` создаёт файл `emails.json` — массив объектов с полями:
   ```json
   {
     "id": 1,
     "category": "billing",
     "urgency": "high",
     "company": "Северный Бор",
     "summary": "суть в 5–10 словах",
     "next_action": "что сделать сотруднику",
     "needs_human": true,
     "draft_reply": "2–3 предложения ответа клиенту"
   }
   ```
2. Требования к prompt: категории — как в упражнении 3; few-shot пример (1–2 объекта); правило для неизвестных значений (`null`, а не выдумка); `needs_human: true`, если в ответе нужно что-то обещать (деньги, сроки, замену) — с объяснением *почему* это правило; черновик ответа не обещает того, чего нет в письме.
3. Сохрани prompt в `ex7-prompt.md` и запусти.
4. Проверь, что JSON корректный: попроси Claude выполнить `python -m json.tool emails.json` (или `python3 …`) и прочитай вывод. Если Python нет — попроси Claude проверить другим способом и опиши каким.
5. Выборочно проверь 3 письма: верны ли категория, `needs_human`, нет ли в черновике обещаний «из воздуха».
6. Если есть ошибки — улучши prompt, а не результат.

**Что сдать на проверку:** `ex7-prompt.md`, `emails.json`, вывод проверки JSON, 3–5 предложений о найденных ошибках и как ты их исправил prompt'ом.

**Критерии готовности:**
- [ ] `emails.json` проходит проверку `json.tool` (корректный JSON, 10 объектов)
- [ ] у всех объектов одинаковый набор полей; неизвестные значения — `null`
- [ ] в черновиках нет конкретных обещаний (сроки, суммы, бесплатная замена), если их нет в письме; такие письма помечены `needs_human: true`
- [ ] prompt содержит причину правила `needs_human`
