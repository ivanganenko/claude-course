## Упражнение 1. Цепочка из 3 prompts  ·  ⏱ ~40 мин  ·  обязательное

**Цель:** проанализировать документ цепочкой «извлечение → анализ → текст» и сравнить с одним большим prompt.
**Зачем:** цепочки — основной способ надёжно делать большую работу с Claude. Ты увидишь, где одношаговый подход теряет качество и почему промежуточные файлы упрощают проверку.

**Шаги:**
1. **Один prompt (для сравнения).** Попроси: `По @report.md напиши служебную записку генеральному директору: главные проблемы квартала, их причины и что нужно решить. Не больше 1 страницы. Сохрани в chain/0-one-shot.md.`
2. `/clear`. **Шаг 1 — извлечение.** Напиши prompt, который извлекает из `@report.md` факты по темам (выручка, регионы, клиенты, поддержка, персонал, риски) с цифрами и дословными цитатами, и **ничего не анализирует**. Результат → `chain/1-facts.md`. Проверь 3–4 цифры по отчёту.
3. `/clear`. **Шаг 2 — анализ.** Prompt, который работает **только** с `@chain/1-facts.md`: главные проблемы, их вероятные причины (со ссылкой на факты), противоречия в отчёте. Результат → `chain/2-analysis.md`.
4. `/clear`. **Шаг 3 — текст.** Prompt, который по `@chain/2-analysis.md` пишет записку директору (аудитория, цель, формат, длина). Результат → `chain/3-memo.md`.
5. Сохрани три prompt в `chain/prompts.md`.
6. Сравни `0-one-shot.md` и `3-memo.md`: какие проблемы и противоречия нашлись в каждом? Есть ли в одной из версий неверные цифры?

**Что сдать на проверку:** папка `chain/` (4 результата + `prompts.md`); в `observations.md` — сравнение (5–7 предложений): что дала цепочка, где было бы легче найти ошибку.

**Критерии готовности:**
- [ ] три шага выполнены с `/clear` между ними, каждый шаг читает только файл предыдущего шага
- [ ] в `1-facts.md` есть цитаты, и нет выводов/оценок
- [ ] в `2-analysis.md` найдено расхождение «12% vs 9,8%» и противоречие про «стабильную поддержку»
- [ ] `3-memo.md` адресована директору: есть решения, которые от него нужны
- [ ] сравнение с одношаговой версией опирается на конкретные различия

## Упражнение 2. Интервью: Claude спрашивает до выполнения  ·  ⏱ ~30 мин  ·  обязательное

**Цель:** сравнить результат «сразу сделай» и «сначала спроси меня».
**Зачем:** в задачах, где ты сам не всё продумал, вопросы Claude показывают пробелы в постановке — до того, как ты потратишь время на чтение неподходящего результата.

**Шаги:**
1. Задача (ты — руководитель поддержки «Полярной Совы», контекст — `report.md`, разделы 5 и 10): **регламент отдельной очереди поддержки для клиентов «Сервис Премиум»**.
2. **Без интервью:** `По @report.md составь регламент работы отдельной очереди поддержки для клиентов «Сервис Премиум». Сохрани в interview/without.md.`
3. `/clear`. **С интервью:** напиши prompt, где Claude должен сначала задать до 7 вопросов (самые важные первыми) и не начинать, пока ты не ответишь; если ты ответишь «не знаю» — предложить вариант по умолчанию и пометить его.
4. Ответь на вопросы (придумай правдоподобные ответы в роли руководителя; можно опираться на отчёт и заметки встречи). Попроси результат → `interview/with.md`.
5. Сохрани вопросы Claude и свои ответы в `interview/dialog.md`.
6. Сравни два регламента: что в `with.md` есть такого, чего нет в `without.md`? Какие предположения `without.md` сделал «втихую»?

**Что сдать на проверку:** `interview/without.md`, `interview/with.md`, `interview/dialog.md`; в `observations.md` — 4–6 предложений сравнения и список из 2–3 «скрытых предположений» версии без интервью.

**Критерии готовности:**
- [ ] prompt с интервью явно запрещает начинать до ответов и ограничивает число вопросов
- [ ] вопросы и ответы сохранены
- [ ] найдены конкретные скрытые предположения в версии без интервью
- [ ] вывод: в каких задачах ты будешь использовать интервью, а в каких нет — с причиной

## Упражнение 3. Plan mode: план → проверка → выполнение  ·  ⏱ ~40 мин  ·  обязательное

**Цель:** провести многошаговую задачу через plan mode: исследование, план, правка плана, выполнение, проверка.
**Зачем:** на задачах с несколькими файлами и действиями ошибку дешевле поймать в плане, чем в результате. Plan mode гарантирует, что во время обсуждения ничего не изменится.

**Выбери вариант:**
- **A (если установлен Python 3 — проверь `python --version` или `python3 --version`):** скрипт `sales_report.py`, который читает `sales.csv` и создаёт `sales-summary.md`: выручка по регионам, менеджерам и категориям, итог, список аномалий данных.
- **B (без Python):** папка `onboarding/` для нового менеджера региона «Запад»: 4 документа (о компании и продуктах, ситуация в регионе, план первых двух недель, контакты и регламенты — без реальных персональных данных) на основе `report.md` и `meeting-notes.txt`.

**Шаги:**
1. Включи plan mode (Shift+Tab, пока индикатор не покажет plan mode).
2. Опиши задачу (вариант A или B) и попроси план: какие файлы будут созданы/изменены, какие шаги, **как будет проверен результат**, какие предположения сделаны.
3. Проверь план по таблице из README (раздел 3). Найди **минимум одну** вещь, которую нужно изменить (например, добавить шаг проверки, уточнить обработку возвратов, убрать лишний файл), и попроси обновить план.
4. Сохрани финальный план в `plan.md` (попроси Claude или скопируй).
5. Выйди из plan mode и разреши выполнение (в режиме `default`, читая diff).
6. Проверь результат: для A — запусти скрипт (`!python sales_report.py` или `!python3 sales_report.py`) и сверь итог и выручку двух регионов с самостоятельным подсчётом (например, в Excel); для B — прочитай документы и проверь, что факты совпадают с отчётом.

**Что сдать на проверку:** `plan.md`; результат (A: `sales_report.py` + `sales-summary.md`; B: папка `onboarding/`); в `observations.md` — что ты изменил в плане и почему, совпал ли результат с планом.

**Критерии готовности:**
- [ ] план составлен в plan mode, в нём есть файлы, шаги, проверка и предположения
- [ ] минимум одна правка плана до выполнения, с причиной
- [ ] результат выполнен по плану и проверен независимо (A: цифры совпадают; B: факты совпадают с источниками)
- [ ] A: в сводке отмечены возврат и строка без менеджера; B: в документах нет выдуманных фактов о компании

## Упражнение 4. Критерии качества, самопроверка и обратная связь  ·  ⏱ ~30 мин  ·  обязательное

**Цель:** задать критерии, получить самопроверку от Claude и улучшить результат за две итерации конкретной обратной связью.
**Зачем:** «сделай лучше» не работает. Критерии и точная обратная связь — то, что превращает средний результат в хороший за 2–3 шага, а не за 10.

**Шаги:**
1. Задача: ответ клиенту из письма 6 в `emails.txt` («Горный Ключ», тариф «Премиум»). Факты для ответа: признаём нарушение срока ответа; с 1 ноября — отдельная очередь «Премиум»; компенсация — бесплатный месяц обслуживания; сегодня с клиентом свяжется руководитель поддержки.
2. Запиши в `quality/criteria.md` 5–6 критериев хорошего ответа (проверяемых: не «хороший тон», а «нет слов "к сожалению" больше одного раза» или «не длиннее 120 слов»).
3. Попроси Claude написать ответ по фактам и критериям, затем **проверить себя** по каждому критерию (✅/❌ + почему) и исправить. Результат → `quality/v1.md` (вместе с самопроверкой).
4. Проверь v1 **сам** по тем же критериям. Совпадает ли твоя оценка с самопроверкой Claude?
5. Дай **конкретную** обратную связь (что, где, каким должно быть) → `quality/v2.md`. Ещё раз → `quality/v3.md`.
6. В `quality/feedback.md` запиши обе свои обратные связи и что изменилось после каждой.

**Что сдать на проверку:** папка `quality/` (criteria, v1–v3, feedback); в `observations.md` — где самопроверка Claude ошиблась или была слишком мягкой (если было), и какую правку ты бы перенёс в шаблон навсегда.

**Критерии готовности:**
- [ ] критерии проверяемые (по каждому можно однозначно сказать ✅ или ❌)
- [ ] в v1 есть самопроверка Claude по каждому критерию
- [ ] есть твоя независимая проверка v1 и сравнение с самопроверкой
- [ ] обе обратные связи конкретные: что, где, каким должно быть
- [ ] v3 удовлетворяет всем критериям и не содержит обещаний сверх фактов

## Упражнение 5. Эксперимент: `/compact` vs `/clear` vs новая сессия  ·  ⏱ ~35 мин  ·  обязательное

**Цель:** увидеть, что сохраняется и что теряется при сжатии и очистке context.
**Зачем:** в длинной работе ты будешь регулярно выбирать между `/compact`, `/clear` и новой сессией. Решение должно опираться на понимание, а не на привычку.

**Шаги:**
1. Начни новую сессию в `~/claude-practice/04-context`. Сделай подряд 6–8 небольших задач, создав «историю» (не забывай про разнообразие):
   - прочитай `@report.md` и `@sales.csv`;
   - договорись с Claude о правиле: «Во всех моих отчётах суммы — в тыс. ₽ с одним знаком после запятой»;
   - попроси короткую сводку по поддержке; попроси переписать её иначе; откажись от второго варианта и вернись к первому;
   - спроси о каком-нибудь мелком факте (например, сколько заказов не удалось принять 14 августа);
   - договорись о ещё одной детали: «Название нашей встречи — "Пятничный разбор"».
2. Выполни `/context` и запиши объём.
3. Выполни `/compact` **с инструкциями**: сохранить правило о суммах и название встречи. Снова `/context`.
4. Задай 3 контрольных вопроса: (а) как я прошу оформлять суммы? (б) как называется встреча? (в) какой вариант сводки по поддержке мы выбрали и почему отказались от второго? Запиши ответы.
5. Выполни `/clear`, задай те же 3 вопроса. Запиши.
6. Создай файл `decisions.md` с двумя договорённостями (правило сумм и название встречи). Выполни `/clear`, затем: `Прочитай @decisions.md. Как я прошу оформлять суммы?`
7. Заверши сессию, открой новую через `claude -c` и задай вопрос (в) ещё раз. Затем открой полностью новую сессию (`claude`) и задай его же.

**Что сдать на проверку:** `decisions.md`; в `observations.md` — таблица `момент | объём context | ответ на (а) | (б) | (в)` и вывод (4–6 предложений): когда что использовать.

**Критерии готовности:**
- [ ] замеры `/context` до и после `/compact`
- [ ] `/compact` выполнен с инструкциями
- [ ] ответы на 3 вопроса записаны после `/compact`, `/clear`, файла, `claude -c` и новой сессии
- [ ] вывод объясняет, почему «важное — в файл» надёжнее и `/compact`, и истории сессии

## Упражнение 7. ⭐ Большой документ: сначала цитаты  ·  ⏱ ~40 мин  ·  со звёздочкой

**Цель:** сравнить ответы «сразу» и «сначала цитаты, потом ответ» на вопросах, требующих сопоставления разных частей документа.
**Зачем:** самые опасные ошибки по документам — в вопросах, где нужно связать два раздела или заметить, что данных нет. Приём «цитаты сначала» делает такие ответы точнее и проверяемее.

**Шаги:**
1. Вопросы к `report.md`:
   1. Какая доля обращений клиентов «Премиум» **не** получила первый ответ в течение 2 часов, и как это связано с причинами оттока?
   2. Сколько человек работало в компании на начало квартала и сколько менеджеров по продажам уволилось за квартал?
   3. Выполнена ли цель по «Сервис Премиум» и как запуск повлиял на нагрузку поддержки?
   4. Какие рекомендации отчёта напрямую следуют из опроса ушедших клиентов?
   5. Можно ли по отчёту утверждать, что CSAT упал из-за клиентов «Премиум»?
   6. На сколько выросла выручка региона «Центр» и какую долю всего прироста выручки компании это составило?
2. Сначала **сам** определи правильные ответы по отчёту (запиши в `quotes/answers-key.md`). Это эталон для оценки.
3. **Вариант A:** все вопросы одним сообщением, `@report.md` в начале, вопросы в конце, без особых инструкций → `quotes/a.md`.
4. `/clear`. **Вариант B:** документ в начале, затем инструкция «сначала выпиши релевантные цитаты в `<quotes>`, потом ответь в `<answer>` только по ним; если данных нет — скажи» → `quotes/b.md`.
5. Оцени оба варианта по эталону: верно / частично / неверно; отдельно — где модель сказала «нет данных» или не заметила, что данных недостаточно (вопрос 5).
6. Повтори вариант B ещё раз (после `/clear`) — стабилен ли результат?

**Что сдать на проверку:** `quotes/answers-key.md`, `quotes/a.md`, `quotes/b.md` (и повтор B), таблица оценки `вопрос | эталон | A | B | B-повтор` в `quotes/score.md`, вывод (3–5 предложений).

**Критерии готовности:**
- [ ] эталонные ответы определены самостоятельно и верны
- [ ] в варианте B цитаты дословные (проверено поиском по тексту)
- [ ] оценка по всем 6 вопросам для A, B и повтора B
- [ ] вывод: в каких типах вопросов «цитаты сначала» помогли, а в каких разницы не было — и почему
