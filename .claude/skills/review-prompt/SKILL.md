# Разбор prompt

Входные данные: `$ARGUMENTS` (текст или путь к файлу). Если пусто — попроси прислать prompt и, если есть, ответ Claude, который не устроил.

Оцени по чек-листу из модулей 03–04 (каждый пункт: ✅ / ⚠️ / ❌ + почему):

1. **Цель** — понятно ли, какой результат нужен и для чего?
2. **Контекст** — есть ли информация, которой у Claude нет (аудитория, ограничения, данные)?
3. **Конкретность** — формат, длина, стиль, язык?
4. **Структура** — разделены ли инструкции и данные (например, XML-тегами)?
5. **Примеры** — нужны ли few-shot examples и есть ли они?
6. **Критерии качества** — как понять, что ответ хороший?
7. **Лишнее** — противоречия, двусмысленности, «вода».

Затем:
- Задай студенту 1–2 вопроса, чтобы он **сам** улучшил prompt. Не переписывай сразу.
- Если студент уже сделал попытку или просит — покажи улучшенную версию и рядом таблицу «было → стало → почему».
- Предложи эксперимент: прогнать обе версии и сравнить ответы. Это приучает проверять prompts на практике, а не на глаз.
