# Рубрика модуля 02

> Для агента-преподавателя. Большая часть результатов — файлы в `~/claude-practice/02-basics/`. Если нет доступа — попроси студента перезапустить учителя `claude --add-dir ~/claude-practice` (PowerShell: `claude --add-dir $HOME\claude-practice`).
> Главное в модуле — **контроль над агентом**: студент понимает, где он находится, что Claude собирается сделать, и умеет остановить/откатить. Проверяй именно это, а не красоту файлов.
> Интерфейс Claude Code меняется между версиями (формулировки диалогов разрешений, порядок режимов, `/cost` vs `/usage`). Если наблюдения студента отличаются от README — это не ошибка студента; попроси свериться с `/help`.

## Упражнение 1. Установка и терминал

**Критерии**
- Обязательные: `claude --version` работает; `claude doctor` запущен; на Windows — `git --version` работает; студент объясняет `pwd`, `cd ..`, `cd ~`.
- Желательные: студент использовал Tab; понимает разницу путей Windows (`\`) и macOS/Linux (`/`).

**Эталон / пример хорошего решения**

```text
PS C:\Users\anna> pwd
Path
----
C:\Users\anna

PS C:\Users\anna> claude --version
<номер версии> (Claude Code)

PS C:\Users\anna> claude doctor
… проверки пройдены, предупреждений нет
```

Объяснение: `pwd` — показать текущую папку; `cd ..` — подняться на уровень выше; `cd ~` — перейти в домашнюю папку из любого места.

**Частые ошибки**
- *«claude не распознано» сразу после установки.* Терминал не перезапущен. **Почему:** список путей к программам терминал читает при старте. Попроси закрыть и открыть окно, затем `claude doctor`.
- *Запустил установку в «Командной строке» (cmd) вместо PowerShell.* `irm … | iex` — команда PowerShell. Объясни разницу оболочек.
- *Нет Git for Windows.* Claude Code на Windows использует Git Bash; без него будут проблемы с командами. Отправь на https://git-scm.com/downloads/win.
- *Ошибки прав/корпоративный прокси.* Не выдумывай решения: попроси вывод `claude doctor` и отправь в раздел установки/troubleshooting на https://code.claude.com/docs; при корпоративных ограничениях — к IT-отделу.

**Критерии**
- Обязательные: `tasks.md` с колонками «Задача», «Ответственный», «Срок», «Статус» + раздел «Открытые вопросы»; использован `@`; описана разница `default`/`acceptEdits`; студент проверил содержимое.

**Эталон / пример хорошего решения**

```markdown
| Задача | Ответственный | Срок | Статус |
|--------|---------------|------|--------|
| Дожать подрядчика: смета и сроки по сайту, смету отправить и Марине | Тимур | до пятницы (2 или 9 окт.? уточнить) | не начато |
| Список клиентов «Запада» для передачи менеджерам «Центра» | Игорь Н. | на этой неделе (до 2–4 окт.?) | не начато |

| Согласовать с директором найм 2 сотрудников поддержки (1 сейчас, 1 с января) | Ольга | 10 окт. | не начато |
| Тексты для страниц ЛК + обновлённый FAQ | Света | 20 окт. | не начато |
| Бюджет на ставки поддержки | Марина | не указан (частично уже ответила на встрече) | не начато |

## Открытые вопросы
- Точная дата запуска сайта — после сметы, ориентир декабрь.
- «До пятницы» — какая пятница?
- FAQ закреплён за Светой неуверенно («вроде да»).
- Корпоратив — обсуждение перенесено.
```

Наблюдения: diff показывал строки с `+` (добавлены) и `-` (удалены); при сортировке поменялся порядок строк целиком. В `acceptEdits` правка прошла без вопроса — быстрее, но я узнал о ней только по сообщению Claude.

**Частые ошибки**
- *Разрешает правки не читая.* Спроси: «Что изменилось в файле на шаге 3?» Если студент не знает — объясни, что diff — единственная точка контроля в `default`. **Почему:** привычка «да не глядя» опаснее, чем осознанный `acceptEdits`.
- *Таблица принята, хотя в ней неверные данные (например, «Света — 15-е»).* Это ошибка контроля, а не Claude: в заметках срок потом перенесён. Наведи вопросом: «Перечитай конец заметок — сроки не менялись?» Хорошо связать с модулем 03 (заметка: дальше научимся писать prompt так, чтобы Claude сам отмечал противоречия).
- *Не нашёл, где включён режим.* Покажи индикатор под полем ввода; порядок режимов — по кругу Shift+Tab.
- *Скопировал файл не туда (путь курса другой).* Помоги найти путь: `pwd` в окне учителя.

## Упражнение 4. Отказ в разрешении

**Критерии**
- Обязательные: `meeting-notes.txt` в `archive/`; описаны реакции на отказ с объяснением и без; записана команда, которую Claude хотел выполнить, и её смысл.
- Желательные: студент заметил, что после отказа без объяснения Claude спрашивает, что делать, или предлагает альтернативы, но не выполняет действие «в обход».

**Эталон / пример хорошего решения**

```markdown
## Упр. 4
- Удаление: Claude хотел выполнить `rm meeting-notes.txt` (удалить файл). Я отказал и попросил архивировать — Claude предложил `mkdir archive` и `mv meeting-notes.txt archive/` (создать папку и переместить файл). Разрешил.
- Переименование без объяснения: Claude сообщил, что действие отклонено, и спросил, как поступить (оставить имя или выбрать другое). Сам ничего не сделал.
- Вывод: отказ с объяснением — быстрее приводит к нужному результату; отказ без объяснения просто останавливает Claude.
```

**Частые ошибки**
- *Нажал «да» по привычке, файл удалён.* Не страшно — это и есть урок. Скопируй файл из `practice/texts/` заново и попроси повторить. Объясни, почему rewind может не вернуть удаление через команду (связь с упр. 5).
- *Не понимает команды `rm`, `mv`, `mkdir`.* Коротко объясни каждую и подчеркни: читать предлагаемые команды — обязательный навык; если команда непонятна — спроси Claude «что делает эта команда?» **до** разрешения.
- *Claude в версии студента переместил файл другим способом (например, через Write+удаление).* Засчитывай, если результат и наблюдения верны.

## Упражнение 5. Rewind

**Критерии**
- Обязательные: `poem.md` откатан к версии до «делового стиля»; проведён эксперимент с `temp.txt`; объяснено ограничение отката.
- Желательные: студент заметил, что откат разговора убирает и сообщения после точки, а Claude «не помнит» отменённых шагов.

**Эталон / пример хорошего решения**

```markdown
## Упр. 5
- После Esc Esc выбрал сообщение «Перепиши poem.md в стиле делового письма» и откатил разговор и код. В poem.md снова первое четверостишие про понедельник, второго четверостишия нет.
- temp.txt, созданный через `!echo`, после отката остался на месте. Rewind отслеживает правки, сделанные инструментами редактирования Claude, а команды в терминале — нет: откат не знает, что они изменили.
- Вывод: rewind — для быстрых экспериментов с правками Claude; для настоящей истории изменений нужен git (модуль 05).
```

Примечание: поведение отката для файлов, созданных командами, может зависеть от версии. Если у студента `temp.txt` исчез — засчитывай, если наблюдение записано честно и студент понимает общий принцип: на откат команд терминала полагаться нельзя, нужна резервная копия/git.

**Частые ошибки**
- *Откатил только разговор, а файл не изменился, и студент решил, что rewind «не работает».* Объясни разницу вариантов «разговор / файлы / оба» (если в его версии есть выбор).
- *Нажал Esc один раз и ничего не произошло.* Один Esc прерывает текущее действие; меню отката — двойной Esc или `/rewind`.
- *Вывод «rewind заменяет git».* Нет: rewind живёт внутри сессий Claude Code и не видит команд терминала и ручных правок. **Почему важно:** иначе в модуле 05 студент не будет коммитить перед большими изменениями.

## Упражнение 6. Что съедает context

**Критерии**
- Обязательные: 4 замера `/context`; прирост от каждого файла; соотношение символов на token; объяснение ненулевого объёма после `/clear`.
- Желательные: студент заметил, что в прирост входят не только файл, но и его вопрос и ответ Claude; сравнил с оценкой из модуля 01.

**Эталон / пример хорошего решения**

Справка для проверки: `report.md` ≈ 7 000 символов, `sales.csv` ≈ 2 600 символов (30 строк данных + заголовок). Конкретные числа tokens у студента будут свои — проверяй логику, а не цифры.

```markdown
## Упр. 6
| Момент | Context |
|--------|---------|
| после /clear | ≈ N₀ (системные инструкции, описания tools, файлы памяти) |
| + report.md | N₀ + ≈ 3–4 тыс. |
| + sales.csv | ещё + ≈ 1,5–2 тыс. |
| после /clear | снова ≈ N₀ |

- Соотношение: 7 000 символов / ≈ 3 300 tokens ≈ 2,1 символа на token для русского текста с таблицами — ближе к нижней границе моей оценки из модуля 01 (символы/2 … символы/3).
- /cost показал расход tokens сессии (в моей версии — …).
- Вывод 1: файл в context «стоит» примерно столько, сколько я и оценивал; плюс ответы Claude тоже занимают место.
- Вывод 2: /clear сбрасывает разговор, но не базовую нагрузку — системные инструкции и описания tools загружаются всегда.
```

**Частые ошибки**
- *Не сделал `/clear` перед первым замером* — тогда в базе есть остатки прошлых упражнений. Попроси переделать замер.
- *Посчитал прирост только от файла, не учтя ответ Claude.* Не ошибка, но обрати внимание: прирост = файл + вопрос + ответ.
- *Ждал, что после `/clear` будет 0.* Объясни базовую нагрузку. **Почему важно:** в модулях 06–08 студент будет добавлять CLAUDE.md, skills и MCP servers — всё это увеличивает базовую нагрузку, и полезно помнить, откуда она берётся.
- *`/cost` показывает не то, что в README.* Нормально: зависит от версии и типа аккаунта. Попроси `/help`.

## Упражнение 7. ⭐ Наведи порядок в папке

**Критерии**
- Обязательные: план в режиме `plan` с корректировкой; минимум один отказ с альтернативой; все файлы разложены, имена единообразны; `claude -c` проверен; `README.md` создан на другой модели и есть наблюдение.
- Желательные: студент проверял результат через `!ls -R`, а не верил отчёту Claude; заметил, что в режиме `plan` Claude ничего не менял.

**Эталон / пример хорошего решения**

Итоговая структура (пример):

```text
downloads/
  README.md
  contracts/   2026-09-15_dogovor-postavki.txt, 2026-09-20_dop-soglashenie.txt
  invoices/    2026-09-01_schet-4471.txt, 2026-09-25_schet-4502.txt
  photos/      2026-09-10_ofis-1.jpg.txt, ...
  presentations/ ...
  spreadsheets/  ...
  screenshots/   ...
```

Наблюдения (пример): «В плане Claude предлагал папку `misc` для двух файлов — попросил распределить их по существующим. При выполнении отклонил переименование на английский (`invoice_...`), попросил транслит единообразно. После `claude -c` Claude пересказал, что мы сделали, и сказал, что все 12 файлов разложены. На haiku README получился короче, но для такой задачи этого достаточно».

**Частые ошибки**
- *Сразу попросил выполнить без плана.* Попроси повторить с `plan`. **Почему:** на многошаговых задачах с переименованиями ошибку в плане исправить дешевле, чем в 12 перемещённых файлах.
- *`claude -c` запущен из другой папки* — тогда продолжается не та сессия или её нет. Объясни: сессии привязаны к папке.
- *Модель не переключилась обратно.* Мелочь, но напомни: выбранная модель влияет на качество следующих задач.

## Quiz

1. **Что произойдёт, если запустить `claude` в папке курса и делать там упражнения?**
   → Практическая сессия загрузит `CLAUDE.md` и skills учителя (из текущей/родительских папок) и начнёт вести себя как преподаватель; эксперимент будет «грязным».
   → *Почему:* проверяет понимание, что поведение Claude Code зависит от папки запуска.
2. **Чем отличаются `default`, `acceptEdits` и `plan`?**
   → `default` спрашивает перед правками и командами; `acceptEdits` правит файлы без вопросов, команды спрашивает; `plan` только читает и предлагает план.
   → *Почему:* важно, чтобы студент связывал режим с ситуацией, а не просто перечислял.
3. **Почему `bypassPermissions` опасен и где он допустим?**
   → Агент выполняет любые действия без подтверждения, включая удаление и команды с правами пользователя. Допустим только в изолированной среде (VM, контейнер).
   → *Почему:* ошибка агента без контроля = реальный ущерб.
4. **Что попадает в context, когда ты пишешь `@report.md`?**
   → Содержимое файла (плюс твоё сообщение и затем ответ Claude).
   → *Почему:* связь `@` и расхода context — основа модуля 04.
5. **Ситуация: Claude начал переписывать не тот файл, процесс идёт. Что сделаешь?**
   → Нажму Esc (прервать), затем при необходимости Esc Esc / `/rewind`, чтобы откатить уже сделанные правки, и уточню задачу.
   → *Почему:* не ждать окончания — правильный рефлекс.
6. **Ситуация: вчера ты работал с Claude над файлами в папке, сегодня хочешь продолжить с того же места. Что сделаешь?**
   → `cd` в ту же папку и `claude -c` (или `claude`, затем `/resume` и выбрать сессию).
   → *Почему:* сессии привязаны к папке; проверяет знание команд продолжения.
7. **Ситуация: Claude предлагает выполнить команду, которую ты не понимаешь. Что сделаешь?**
   → Откажу или не разрешу сразу; спрошу Claude, что делает команда и зачем; разрешу, только когда понятно.
   → *Почему:* читать команды перед разрешением — ключевой навык безопасности.
8. **Ситуация: ты закончил задачу про отчёт и переходишь к письмам клиентам, не связанным с отчётом. Что сделаешь с сессией и почему?**
   → `/clear` (или новая сессия): старый разговор занимает context и может сбивать Claude.
   → *Почему:* подводка к модулю 04; ответ «ничего, продолжу» — повод объяснить вред длинного нерелевантного контекста.

## Ответы на «Вопросы для самопроверки» из README

1. Claude Code работает с папкой запуска: читает и меняет файлы в ней, подхватывает `CLAUDE.md`/настройки из неё и родительских папок. В домашней папке агенту были бы доступны все личные документы, а задача — размыта; ошибка могла бы затронуть что угодно.
2. `cd ..` — на один уровень вверх от текущей папки; `cd ~` — в домашнюю папку из любого места.
3. Diff: какие строки добавлены/удалены, тот ли это файл, нет ли лишних изменений; для команды — что она делает и в какой папке.
4. `default` спрашивает о правках и командах; `acceptEdits` правит файлы без вопросов (команды по-прежнему спрашивает); `bypassPermissions` не спрашивает ничего — опасно, только для изолированных сред. `acceptEdits` уместен, когда задача и план понятны, правок много, и есть способ откатить (rewind, git).
5. Действие не выполняется, Claude получает сообщение об отказе и ждёт указаний или предлагает альтернативу. Направить — объяснить в ответе, что сделать иначе.
6. Esc — прервать текущее действие, разговор сохраняется. Esc Esc — меню отката к прошлому сообщению/checkpoint (разговор и/или файлы). `/clear` — очистить историю разговора, файлы не меняются.
7. Скорее всего нет: rewind отслеживает правки, сделанные инструментами редактирования Claude; удаление через команду терминала откатом не отслеживается. Нужны резервные копии/git.
