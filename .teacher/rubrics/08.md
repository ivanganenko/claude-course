## Справка для преподавателя

- `practice/mcp-server/requirements.txt` фиксирует `mcp[cli]>=1.2,<2`. В SDK 2.x модуль `mcp.server.fastmcp` удалён (FastMCP переименован), и код курса падает с `No module named 'mcp.server.fastmcp'`. Если студент ставил `mcp` вручную без ограничения — первым делом проверь версию: `pip show mcp`.
- Самая частая причина «server не подключается» — запуск не тем Python (не из `.venv`) или относительный путь к `server.py`. Попроси студента выполнить ту же команду, что после `--`, руками в терминале: ошибка станет видна.
- Эталонные решения ниже проверены реальным MCP client (stdio) на SDK 1.x.

## Упражнение 1. Подключить готовый server

**Критерии**
- Обязательные: server подключён (`claude mcp list`, `/mcp`); названо полное имя tool `mcp__playwright__<tool>`; задача шага 6 выполнена через tools; замечено, что tools занимают context.
- Желательные: сверка команды с README сервера; наблюдение о количестве вызовов в многошаговой задаче.

**Эталон**

```bash
node --version && npx --version
claude mcp add --transport stdio playwright -- npx @playwright/mcp@latest
claude mcp list          # playwright: npx @playwright/mcp@latest - ✓ Connected (формат вывода может отличаться)
```
В сессии: `/mcp` → `playwright` подключён, tools вида `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_take_screenshot` (набор зависит от версии). Запрос разрешения: `mcp__playwright__browser_navigate`. Ответ: «Заголовок — Example Domain; одна ссылка — More information…». Многошаговая задача: 3–6 вызовов (navigate → snapshot → click → snapshot). `/context`: MCP tools занимают заметную часть (тысячи tokens).

**Частые ошибки**
- *Нет Node.js / `npx` не найден.* → Не блокировать модуль: разреши сделать 2–3 первыми, к 1 вернуться после установки Node.js LTS. Объясни: server на npm запускается через Node, как Python-server через Python.
- *На Windows server не стартует через `npx`.* → Отправь в раздел Windows документации Claude Code по MCP; не выдумывай обёрток — сверяйтесь с docs.
- *Claude ответил «по памяти», без вызова tools* (example.com известен модели). → Попроси повторить с менее известной страницей или явно: «используй браузер». Хороший повод обсудить: проверяй, что ответ действительно получен из tool.
- *Добавил server в папке курса.* → Local scope привязан к проекту; в практической папке его не будет. Объясни scope и попроси добавить в практической папке (или `--scope user`, если осознанно).
- *Включил «разрешить всегда» для всех действий браузера, не читая.* → Обсуди риски: браузер с твоими cookies может делать действия от твоего имени.

## Упражнение 2. Свой server «notes»: второй tool

**Критерии**
- Обязательные: Python из venv, полные пути; два tools в `/mcp`; docstring объясняет формат `name`; несуществующая заметка → понятное сообщение; `../server` не читает `server.py`; нет `print()` в stdout.
- Желательные: защита от выхода из папки через `resolve()` и сравнение с папкой; Claude в первом запросе сначала вызывает `list_notes`, потом `read_note`.

**Эталон** (`server.py` целиком после упражнений 2–3, проверен)

```python
"""MCP server «notes»: даёт Claude доступ к папке с заметками в формате Markdown."""

import os
from pathlib import Path

from mcp.server.fastmcp import FastMCP

NOTES_DIR = Path(os.environ.get("NOTES_DIR", Path(__file__).parent / "notes")).resolve()

mcp = FastMCP("notes")


def _note_path(name: str) -> Path | None:
    """Путь к заметке или None, если имя ведёт за пределы NOTES_DIR / файла нет."""
    path = (NOTES_DIR / f"{name}.md").resolve()
    if path.parent != NOTES_DIR or not path.is_file():
        return None
    return path


@mcp.tool()
def list_notes() -> list[str]:
    """Вернуть список всех заметок (имена файлов без расширения .md), по алфавиту.

    Используй, чтобы узнать, какие заметки существуют, прежде чем читать одну из них.
    """
    return sorted(path.stem for path in NOTES_DIR.glob("*.md"))


@mcp.tool()
def read_note(name: str) -> str:
    """Вернуть полный текст одной заметки.

    name — имя заметки без расширения .md, ровно как его возвращает list_notes
    (например, "project-orion").
    """
    path = _note_path(name)
    if path is None:
        return f"Заметка '{name}' не найдена. Доступные заметки: {', '.join(list_notes())}"
    return path.read_text(encoding="utf-8")


@mcp.tool()
def search_notes(query: str) -> list[str]:
    """Найти строки во всех заметках, где встречается query (без учёта регистра).

    Возвращает список вида "имя-заметки: найденная строка". Используй, когда
    пользователь спрашивает о теме, человеке или проекте, но не называет заметку.
    """
    q = query.lower()
    results = []
    for path in sorted(NOTES_DIR.glob("*.md")):
        for line in path.read_text(encoding="utf-8").splitlines():
            if q in line.lower():
                results.append(f"{path.stem}: {line.strip()}")
    return results or [f"Ничего не найдено по запросу '{query}'"]


@mcp.resource("notes://{name}")
def note_resource(name: str) -> str:
    """Заметка как resource: notes://<имя-заметки>."""
    return read_note(name)


if __name__ == "__main__":
    mcp.run()
```

Проверка (что вернул server): `read_note("../server")` → «Заметка '../server' не найдена. Доступные заметки: ideas, meeting-2026-10-01, project-orion»; `search_notes("Орион")` → 3 строки из двух заметок.

Ответы на шаг 6: «Что известно о проекте Орион?» → `list_notes` → `read_note("project-orion")` (иногда и `meeting-2026-10-01`) → сводка: CRM, пилот 15 ноября, риски. «budget» → сообщение «не найдена» со списком. «../server» → «не найдена».

**Частые ошибки**
- *`ModuleNotFoundError: No module named 'mcp'` в `/mcp`.* → Подключён системный `python`. Объясни, почему Claude Code не видит активированную venv (он запускает процесс сам), и попроси полный путь к `.venv/.../python`.
- *`No module named 'mcp.server.fastmcp'`.* → Установлен mcp 2.x; `pip install -r requirements.txt` в venv (там `<2`).
- *Проверка безопасности через `if ".." in name`.* → Частично работает, но хрупко (абсолютные пути, символические ссылки, другие трюки). Покажи подход `resolve()` + сравнение с папкой как более надёжный и объясни почему: проверяем результат, а не перечисляем плохие варианты.
- *`read_note` бросает исключение на отсутствующую заметку.* → Допустимо (SDK вернёт ошибку модели), но понятное сообщение со списком помогает модели исправиться с первого раза. Обсуди оба варианта.
- *Docstring «Читает заметку».* → Модель не знает, передавать `project-orion` или `project-orion.md` или путь; отсюда лишние ошибочные вызовы.
- *Правки не видны.* → Server запущен старой сессией; нужна новая сессия Claude Code.

## Упражнение 3. Resource и третий tool

**Критерии**
- Обязательные: `search_notes` без учёта регистра и с указанием, где найдено; resource `notes://{name}` с переиспользованием логики; разница tool/resource своими словами; эксперимент с docstring и вывод.
- Желательные: Claude в шаге 4 вызывает `search_notes`, затем `read_note` для деталей; честное описание результата шага 5 (даже если упоминание resource не удалось).

**Эталон** — см. `server.py` выше (функции `search_notes`, `note_resource`).

Разница: «tool — действие, которое модель решает вызвать сама с параметрами; resource — данные по адресу, которые подключает приложение/пользователь как контекст».

Шаг 4: `search_notes("Игорь")` → строки из `meeting-2026-10-01` («Игорь — подготовить список рисков по «Ориону» к пятнице») и `project-orion` («Ответственный с нашей стороны: Игорь Белов») → ответ.

Шаг 6: с docstring «Поиск.» модель чаще идёт обходным путём (`list_notes` + чтение всех заметок по очереди) или передаёт неудачный query; вывод — описание tool управляет выбором так же, как `description` skill.

**Частые ошибки**
- *Resource копирует код `read_note`.* → Две копии логики безопасности разойдутся — и дыра появится в одной из них.
- *`search_notes` возвращает целые заметки.* → Много лишнего в context; цель поиска — показать, где искать, а детали прочитать `read_note`.
- *Студент считает, что resource модель вызывает так же, как tool.* → Разбери таблицу из раздела 2: кто инициирует.
- *Упоминание resource через `@` не сработало.* → Формат зависит от версии; это нормально, если студент проверил docs и описал результат. Не выдумывай формат — сверяйся с документацией.

## Упражнение 4. Project scope и `.mcp.json`

**Критерии**
- Обязательные: `.mcp.json` в корне, корректный JSON, относительные пути; server работает из корня; объяснено, почему не виден в другой папке; описана кросс-платформенная проблема; нет секретов/личных путей.
- Желательные: осмысленный ответ на запрос подтверждения; `NOTES_DIR` через `env`.

**Эталон**

```bash
claude mcp remove notes
# macOS / Linux, в ~/claude-practice/mcp-server
claude mcp add --transport stdio --scope project notes-team -- .venv/bin/python server.py
```
```powershell
# Windows, в ~/claude-practice/mcp-server
claude mcp add --transport stdio --scope project notes-team -- .venv/Scripts/python.exe server.py
```

`.mcp.json` (после шага 8):
```json
{
  "mcpServers": {
    "notes-team": {
      "type": "stdio",
      "command": ".venv/bin/python",
      "args": ["server.py"],
      "env": {
        "NOTES_DIR": "notes"
      }
    }
  }
}
```

Ответы:
- Шаг 4: «Claude Code спросил, доверяю ли я server из `.mcp.json`. Разрешил, потому что сам написал этот файл и server; на чужом репозитории сначала прочитал бы `.mcp.json` и код server».
- Шаг 6: «Не виден: project scope действует только в проекте, где лежит `.mcp.json`».
- Шаг 7: «Путь к Python в venv разный: `.venv/bin/python` на macOS/Linux и `.venv/Scripts/python.exe` на Windows — у коллеги на другой ОС не запустится. Варианты: `"command": "python"` и договорённость, что каждый ставит зависимости в своё окружение; отдельная инструкция в README; или инструмент, который сам управляет окружением (обсуждаем как идею, без установки)».

**Частые ошибки**
- *Абсолютный путь `C:/Users/<имя>/...` в `.mcp.json`.* → Работает только у автора; в командном файле — относительные пути.
- *Обратные слеши без экранирования в JSON (`"C:\Users\..."`).* → Невалидный JSON; `\U` — escape-последовательность. Удвоить слеши или писать прямые.
- *Токен в `"env"` прямо в файле.* → Файл в git — токен утёк. Секреты — в переменных окружения пользователя, в `.mcp.json` — ссылка на переменную (синтаксис — по docs).
- *Server с тем же именем остался в local scope.* → Путаница, какой конфиг работает; поэтому шаг 1 удаляет local-регистрацию.
- *`NOTES_DIR` относительный, а `claude` запущен не из корня.* → Путь считается от рабочей папки процесса. Обсуди компромисс: относительный путь удобен команде, но требует запуска из корня проекта.

## Упражнение 5. Prompt injection через данные

**Критерии**
- Обязательные: эксперимент проведён и записан честно; ≥ 2 слоя защиты вне модели; объяснено, почему нельзя полагаться на «модель заметит»; 3 конкретных правила.
- Желательные: студент отметил, что у server «notes» нет tool записи — опасное действие возможно только через встроенные tools Claude Code, которые требуют разрешения.

**Эталон**

Наблюдение (типичное): Claude сделал сводку и отметил, что в `supplier.md` есть подозрительная инструкция, которую он не выполняет. Если был запрос на создание `HACKED.txt` — студент отказал.

Слои защиты:
1. Server «notes» только читает — tool для записи нет.
2. Создание файла требует разрешения (режим `default`); человек видит запрос.
3. Поведение модели — обучена не выполнять инструкции из данных, но это вероятностная защита, не гарантия.

В `acceptEdits` правки файлов применяются без вопросов — файл мог бы появиться без ведома пользователя.

Правила:
- подключаю servers к внешним данным (веб, почта, тикеты) только с минимальными правами, по возможности read-only;
- после чтения внешних данных внимательно читаю каждый запрос разрешения, не нажимаю «разрешить всегда»;
- не держу секреты в папках, к которым есть доступ у servers, и не работаю с внешними данными в `acceptEdits`/`bypassPermissions`.

**Частые ошибки**
- *«Claude распознал ловушку — значит, риска нет».* → Один успешный прогон не гарантия: формулировки атак разные, модель вероятностна. Защита — в слоях вокруг модели.
- *Ловушка с реально опасной командой (`rm`, отправка данных).* → Остановить: эксперимент должен быть безвредным. Объясни, почему: если защита не сработает, последствия реальны.
- *Правила общие («быть осторожнее»).* → Попроси сформулировать так, чтобы можно было проверить выполнение.

## Упражнение 6. ⭐ MCP server к своим данным (CSV)

**Критерии**
- Обязательные: 3–4 read-only tools с docstrings; путь через env; ошибки колонок; ограничение результата; независимая проверка цифр; вывод «server vs `@файл`».
- Желательные: `describe()` как точка входа, о которой сказано в docstring; сортировка результатов; числа округлены.

**Эталон** (`server.py`, проверен на `practice/texts/sales.csv`)

```python
"""MCP server «sales»: read-only доступ к CSV с продажами."""

import csv
import os
from collections import defaultdict
from pathlib import Path

from mcp.server.fastmcp import FastMCP

CSV_PATH = Path(os.environ.get("SALES_CSV", Path(__file__).parent / "sales.csv"))
MAX_ROWS = 50  # не отдаём модели больше строк за раз — бережём context

mcp = FastMCP("sales")


def _rows() -> list[dict]:
    with CSV_PATH.open(encoding="utf-8", newline="") as f:
        return list(csv.DictReader(f))


def _num(value: str) -> float:
    return float(value.replace(",", ".")) if value else 0.0


@mcp.tool()
def describe() -> dict:
    """Описать таблицу продаж: число строк, колонки, примеры значений.

    Вызывай первым, чтобы узнать названия колонок перед другими запросами.
    """
    rows = _rows()
    columns = list(rows[0].keys()) if rows else []
    examples = {c: sorted({r[c] for r in rows})[:5] for c in columns}
    return {"rows": len(rows), "columns": columns, "examples": examples}


@mcp.tool()
def filter_rows(column: str, value: str) -> list[dict]:
    """Вернуть строки, где column точно равна value (не больше 50 строк).

    Пример: filter_rows("region", "Север").
    """
    rows = _rows()
    if rows and column not in rows[0]:
        raise ValueError(f"Нет колонки '{column}'. Есть: {', '.join(rows[0])}")
    found = [r for r in rows if r[column] == value]
    return found[:MAX_ROWS]


@mcp.tool()
def sum_by(group_column: str, value_column: str) -> dict[str, float]:
    """Сумма value_column по группам group_column, по убыванию.

    Пример: sum_by("manager", "revenue") — выручка по менеджерам.
    """
    rows = _rows()
    for c in (group_column, value_column):
        if rows and c not in rows[0]:
            raise ValueError(f"Нет колонки '{c}'. Есть: {', '.join(rows[0])}")
    totals: dict[str, float] = defaultdict(float)
    for r in rows:
        totals[r[group_column]] += _num(r[value_column])
    return dict(sorted(((k, round(v, 2)) for k, v in totals.items()), key=lambda kv: -kv[1]))


if __name__ == "__main__":
    mcp.run()
```

Подключение (macOS/Linux; на Windows — `.venv\Scripts\python.exe` и путь Windows):
```bash
claude mcp add --transport stdio --env SALES_CSV=$HOME/claude-practice/sales-mcp/sales.csv sales -- ~/claude-practice/sales-mcp/.venv/bin/python ~/claude-practice/sales-mcp/server.py
```

Контрольные цифры по `practice/texts/sales.csv` (30 строк; если файл менялся — пересчитай):
- выручка по регионам: Центр 858 300, Юг 371 220, Север 369 950, Запад 310 204 → лидер — Центр;
- «Расходники» по менеджерам: лидер Борис К. — 274 800;
- скидки больше 10 %: есть строки с `discount_pct` = 15.

Вывод шага 6 (пример): «Через `@sales.csv` Claude видит всю таблицу в context и считает "в уме" — на 30 строках обычно верно, но на тысячах строк не влезет и может ошибиться. Server считает точно, в context попадает только результат; цена — время на разработку и ещё одна программа, которой я доверяю».

**Частые ошибки**
- *Tool `run_python(code)` или `query(sql)` с выполнением произвольного кода.* → Это не read-only доступ к данным, а выполнение чего угодно с твоими правами. Обсуди принцип минимальных прав.
- *Нет лимита строк.* → На реальной таблице результат съест context.
- *Цифры не проверены независимо.* → Без проверки нельзя отличить ошибку server от ошибки интерпретации. Это требование упражнения.
- *Числа как строки в сумме (конкатенация) или float с длинным хвостом.* → Показать `_num` и `round`.
- *Реальная выгрузка с данными клиентов.* → Остановить и заменить на вымышленные/обезличенные данные.

## Quiz

1. **Зачем нужен MCP, если Claude Code и так умеет запускать команды?**
   → Стандартный способ подключить внешние системы (API, БД, браузер) и свои данные с описанными tools; один server работает в разных приложениях. → Если хватает CLI-утилиты — MCP не нужен.
2. **Чем отличаются transports stdio и http?**
   → stdio — локальный процесс, обмен через stdin/stdout; http — удалённый server по URL. → Отсюда разные риски и настройки: локальные права vs сеть и авторизация.
3. **Откуда модель знает, как вызвать твой tool?**
   → Из имени, docstring (описание) и type hints (схема параметров), которые server отдаёт client. → Плохой docstring = неверные или лишние вызовы.
4. **Чем scope `project` отличается от `local`?**
   → `project` пишет `.mcp.json` в корень проекта (в git, для команды); `local` — только у тебя и только в этом проекте. → Личные токены и пути — local/user, общие servers — project.
5. **Ситуация: `/mcp` показывает, что твой server не подключился. Что проверишь?**
   → Запустить команду после `--` руками: тот ли Python (venv), верен ли путь к `server.py`, установлен ли `mcp` нужной версии; нет ли `print()` в stdout. → Ручной запуск показывает реальную ошибку.
6. **Ситуация: коллега предлагает положить API-токен прямо в `.mcp.json`, «так проще». Что ответишь?**
   → Нет: файл в git, токен утечёт; передавать через переменные окружения (`--env`, подстановка переменных по docs). → Утёкший токен нужно отзывать.
7. **Ситуация: Claude прочитал через MCP веб-страницу и после этого просит разрешения удалить папку. Что делаешь?**
   → Отказываю, разбираюсь, откуда инструкция (вероятно, prompt injection из страницы). → Данные из внешних источников могут содержать инструкции; последний рубеж — твоё внимание к разрешениям.
8. **Ситуация: нужно, чтобы Claude смотрел историю коммитов. Писать MCP server для git?**
   → Нет: Claude умеет запускать `git log` через Bash; при повторяющейся процедуре — skill. → MCP добавляет context, сложность и ещё одну доверенную программу; оправдан для внешних систем.

## Ответы на «Вопросы для самопроверки» из README

1. Как USB: один стандарт подключения, и любой «прибор» (server) работает с любым «компьютером» (host). Решает проблему N×M интеграций: каждый сервис пишет server один раз.
2. Tool — действие с параметрами, которое модель решает вызвать сама; resource — данные по адресу (например, `notes://ideas`), которые подключает приложение/пользователь как контекст.
3. В stdio stdout — канал протокола MCP; посторонний текст ломает обмен сообщениями. Отладка — в stderr.
4. Из описания tool (docstring), имени и схемы параметров (type hints), которые server передаёт client при подключении.
5. Запускается ли server тем Python, где установлен `mcp` (venv, полный путь), и верен ли путь к `server.py`. Далее — версия `mcp` (`<2`) и `print()` в stdout.
6. Личный токен — `local` (или `user`, если нужен везде): конфигурация не попадает в git. Server для команды — `project` (`.mcp.json` в репозитории), без секретов и личных путей.
7. Атака, когда инструкции спрятаны в данных (страница, заметка, письмо), которые модель читает через tools. Защищают слои вне модели: минимальные права server (read-only), подтверждения действий, внимательное чтение запросов разрешений, отказ от автоподтверждения при работе с внешними данными.
8. Когда задачу решает существующая CLI-утилита (git) через Bash или процедура без внешней системы (skill). MCP — для структурированного доступа к внешним системам и переиспользования между приложениями.
